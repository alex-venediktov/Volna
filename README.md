# Волна

> **Волна** — сопровождение одной задачи в одном контексте Claude Code: мягкий флоу этапов от
> приёма задачи из трекера до PR и закрытия, с журналом работ и накоплением командного опыта.
> Не оркестратор: процесс ведёт разработчик, «Волна» подсказывает и не даёт потерять нить.

Управляющий документ (требования, решения V1–V10, архитектура, промпты волн W0–W4) —
[`docs/PROMPT-volna-system.md`](docs/PROMPT-volna-system.md).
Текущее состояние работ — [`docs/STATUS.md`](docs/STATUS.md).

## Установка

Внутри сессии Claude Code:

```
/plugin marketplace add alex-venediktov/Volna
/plugin install volna@volna          # процесс: флоу этапов, журнал, команды
/plugin install volna-craft@volna    # ремесло: порт по эталону, стиль кода, тесты, сверка
```

Второй плагин необязателен: без него флоу работает, просто без ремесленных правил.

Одной командой PowerShell, без сторонних менеджеров пакетов:

```powershell
irm https://raw.githubusercontent.com/alex-venediktov/Volna/main/install.ps1 | iex
```

Затем в рабочем репозитории — `/volna:init` (создаст `.volna/` и `.env`) и `/volna:doctor`
(проверит, что заполнено). Автоматическая установка для всей команды через
`.claude/settings.json`, закрепление версии, junction для локальной разработки —
[`docs/INSTALL.md`](docs/INSTALL.md).

## Команды

| Команда | Что делает |
|---|---|
| `/volna:init [путь]` | развернуть проектную часть: `.volna/`, `.env`, правила `.gitignore` |
| `/volna:doctor` | проверить настройки, доступы и гигиену секретов |
| `/volna:task <id>` | принять задачу: гейт чистого дерева, ветка, журнал (этап `intake`) |
| `/volna:status` | где мы: этап k/13, пройденное, пропущенное, открытые вопросы |
| `/volna:stage <этап>` | перейти к любому этапу флоу |
| `/volna:skip <этап> <причина>` | пропустить этап; причина уходит в журнал |
| `/volna:back <этап> [что не так]` | вернуться на повторную итерацию, не переписывая прошлые записи |
| `/volna:journal [текст]` | дописать запись в журнал или показать журнал |
| `/volna:checkpoint` | дописать журнал до восстановимого состояния — перед `/compact` |
| `/volna:close [причина]` | закрытие в трекере: статусы, время, маршрут тестеру (по подтверждению) |
| `/volna:next [id]` | извлечь опыт, снять активную задачу, предложить следующую и `/clear` |
| `/volna:off [on]` | заглушить подсказки «Волны» до конца сессии или включить обратно |

Флоу — 13 этапов: `intake` → `analyze` → `spec` → `plan` → `implement`×N → `advocate` →
`fixtures` → `unit-tests` → `visual` → `commit` → `push-pr` → `close` → `capture`.
Уровни: `required` — только необратимое (`intake`, `commit`, `push-pr`, `close`),
остальное `expected` или `optional`. Законный короткий путь:
`intake → analyze → skip implement → close` («изменения кода не требуются»).

## Два плагина

| Плагин | Содержимое | Кому |
|---|---|---|
| `volna` | скиллы `volna-flow`, `volna-journal`, 12 команд `/volna:*` | всем, кто ведёт задачи |
| `volna-craft` | `port-by-reference`, `code-comments`, `commit-style`, `test-style`, `test-fixtures`, `visual-compare` | тем, кто портирует legacy и держит строгие конвенции |

Ремесленные скиллы обезличены от конкретного продукта: метод — в плагине, проектные детали —
в `.volna/project.md`. Что осталось в рабочем репозитории и как разводить пересечения зон —
[`docs/PROJECT-SKILLS.md`](docs/PROJECT-SKILLS.md), сверка — `/volna:doctor`.

## Что где хранится

| Файл в рабочем репозитории | Назначение | Коммитится |
|---|---|---|
| `.env` | адреса, пути, путь к файлу с токеном | **нет** |
| `.volna/state.json` | указатель на активную задачу | нет |
| `.volna/journal/TASK-<id>.md` | журнал задачи, источник правды о состоянии | нет |
| `.volna/project.md` | команды и конвенции команды | да |
| `.volna/knowledge/<topic>.md` | извлечённый опыт | да |

Секретов в переменных окружения нет: в `.env` лежит **путь** к файлу с токеном, не сам токен.
Адреса серверов и машинные пути — только в `.env`, в репозитории «Волны» их нет.

## Что важно знать про правила

Правила этапов обкатаны примерно на пяти задачах с разным успехом — это **рабочий черновик**.
Правило мешает или неверно → правим его, а не обходим молча; этап, который систематически
пропускается, — повод упростить флоу. Механизм ревизии встроен в этап `capture`.

Предметные скиллы конкретного проекта «Волна» не поставляет: они остаются в рабочем
репозитории, а этапы используют их, если они есть — см.
[`docs/PROJECT-SKILLS.md`](docs/PROJECT-SKILLS.md).
