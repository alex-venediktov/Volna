# Волна

> **Волна** — сопровождение одной задачи в одном контексте Claude Code: мягкий флоу этапов от
> приёма задачи до PR и закрытия, с журналом работ и накоплением командного опыта.
> Не оркестратор: процесс ведёт разработчик, «Волна» подсказывает и не даёт потерять нить.
>
> Задача берётся из трекера по номеру — или заводится своими словами, когда её в трекере нет:
> исследование и разбор проходят тот же флоу и оставляют такой же журнал.

Как это выглядит в работе — [«Как этим пользоваться»](#как-этим-пользоваться): шесть сценариев
от задачи трекера до продолжения через неделю.

Текущее состояние работ, принятые решения и что осталось — [`docs/STATUS.md`](docs/STATUS.md).

## Установка

Внутри сессии Claude Code:

```
/plugin marketplace add alex-venediktov/Volna
/plugin install volna@volna          # процесс: флоу этапов, журнал, команды
/plugin install volna-craft@volna    # ремесло: порт по эталону, стиль кода, тесты, сверка
```

Второй плагин необязателен: без него флоу работает, просто без ремесленных правил.

Одной командой PowerShell, без сторонних менеджеров пакетов:

```powershell
irm https://raw.githubusercontent.com/alex-venediktov/Volna/main/install.ps1 | iex
```

Затем в рабочем репозитории — `/volna:init` (создаст `.volna/` и `.env`) и `/volna:doctor`
(проверит, что заполнено). Автоматическая установка для всей команды через
`.claude/settings.json`, закрепление версии, junction для локальной разработки —
[`docs/INSTALL.md`](docs/INSTALL.md).

## Как этим пользоваться

Шесть сценариев покрывают почти всю работу. В каждом — что набирать и что происходит без вас.

### Задача из трекера: назвать номер и не мешать

```
/volna:task 21571          # и всё: дальше «Волна» идёт сама до сверки результата
```

Один ход проходит `intake` → `analyze` → `spec` → `plan` → `implement` ⇄ `advocate` →
`unit-tests` → `visual`. Вас спросят только там, где без вас нельзя: двусмысленная постановка,
расхождение с эталоном, вердикт «сошлось» на графике, выбор из двух правильных поведений.
Каждый этап дописывает журнал, поэтому прерваться можно в любой момент.

Дальше — три необратимых шага, каждый начинаете вы:

```
/volna:deliver             # коммит, задача-фикс, push, PR - одно «да» на всё
/volna:close               # часы, остаток, статусы, маршрут тестеру
/volna:cleanup             # ветки, временное, индекс знаний
/volna:capture             # опыт в knowledge, замечания к флоу, конец задачи
/clear                     # следующую задачу - с чистого контекста
```

### Исследование без трекера: назвать саму работу

Задачи в трекере нет, деплоить нечего, но журнал и накопленный опыт нужны так же. Аргумент
`/volna:task` — не только номер:

```
/volna:task разобраться, почему вложения TFS приходят с битым именем файла
/volna:task docs/research/attachments.md
```

Первое — постановка текстом, она ложится в журнал дословно. Второе — путь к файлу: он и остаётся
источником, копия не делается. Дальше тот же автопроход и тот же журнал, разница только в концах:

| Шаг | В локальном режиме |
|---|---|
| id задачи | `260730-tfs-attachments-encoding` — дата начала плюс ключевые слова, собирает `intake` |
| `plan` | статус `Active` ставить некуда — шага просто нет |
| `deliver` | есть что зафиксировать → коммит; нечего → пропуск с причиной |
| `close` | часы считаются, итог идёт **в журнал**; трекер не трогается |
| `capture` | как обычно: знание в `knowledge/`, замечания в `feedback.md` |

Так же ведутся разборы, прототипы, «посмотреть, можно ли вообще» и любая работа, которую через
неделю придётся объяснять себе заново.

### Продолжить через день или после `/compact`

```
/volna:status              # где мы: этап, что пройдено, что открыто, следующий шаг
```

Восстановление идёт по журналу, а не по памяти сессии, поэтому продолжать можно с чистого
контекста. Перед сжатием — дописать журнал до восстановимого состояния:

```
/volna:checkpoint          # и после него /compact
```

На длинной задаче (от 8 часов или четыре этапа одним ходом) «Волна» делает эту проверку сама на
границе этапа, не отдавая ход.

### Вернуться назад: та же команда этапа

Отдельных «перейти» и «вернуться» нет — повторный вызов пройденного этапа открывает **новую
итерацию**, а прошлые записи журнала остаются как были:

```
/volna:implement           # правка после находки, красного теста, замечания в PR
/volna:spec                # переоценить полноту, если постановка поехала
```

Причину возврата напишите обычным текстом перед командой — этап возьмёт её оттуда. Цикл
`implement` → `advocate` дальше крутится сам, пока адвокат не скажет «чисто».

### Пропустить этап

Обычный пропуск — просто команда следующего этапа: причина уйдёт в журнал при переходе.

```
/volna:visual              # вместо unit-tests, если тесты не нужны
/volna:skip unit-tests нет логики для юнит-теста     # когда причину важно сформулировать самому
```

### Спросить, что уже известно

```
/volna:recall кодировка вложений
```

Идёт по указателю знаний, записям и прошлым журналам. Пустой ответ — законный: значит, тема новая,
и опыт по ней появится на `capture` этой задачи.

## Команды

**У каждого этапа — своя команда:** одно слово вместо команды с аргументом, поэтому этап
выбирается автокомплитом (набрать `/volna:` и листать), а не по памяти.

| Этап | Команда | Уровень |
|---|---|---|
| 1 принять задачу | `/volna:task <id \| файл \| текст>` | required |
| 2 разбор постановки и эталона | `/volna:analyze` | expected |
| 3 постановка своими словами | `/volna:spec` | expected |
| 4 план по файлам, `Active` в трекере | `/volna:plan` | expected |
| 5 реализация (итераций сколько нужно) | `/volna:implement [что доработать]` | expected |
| 6 адвокат дьявола против решения | `/volna:advocate` | expected |
| 7 оффлайн-снимок заказа | `/volna:fixtures` | optional |
| 8 тесты по конвенциям | `/volna:unit-tests` | expected |
| 9 пиксельная сверка человеком | `/volna:visual` | optional |
| 10 доставка: коммит, задача-фикс, push, PR | `/volna:deliver` | required |
| 11 статусы в трекере, списание времени | `/volna:close [причина]` | required |
| 12 уборка: репозитории, ветки, индекс KB | `/volna:cleanup` | expected |
| 13 опыт в knowledge, замечания к флоу, завершение | `/volna:capture` | expected |

Этапы 1–9 (`intake` → `visual`) идут **автопроходом**: пока продолжение единственное, «Волна»
переходит к следующему этапу сама, без команды. Ход отдаётся человеку на развилке, СТОП-критерии,
там, где нужен он сам (вердикт сверки, доступ), и перед доставкой. Команды этапов остаются —
ими человек возвращается назад и открывает новую итерацию.

Служебные, вне флоу:

| Команда | Что делает |
|---|---|
| `/volna:init [путь]` | развернуть проектную часть: `.volna/`, `.env`, правила `.gitignore` |
| `/volna:doctor` | проверить настройки, доступы и гигиену секретов |
| `/volna:recall <тема>` | найти в знаниях и прошлых журналах то, что относится к теме |
| `/volna:status` | где мы: этап k/13, карта этапов, пройденное, пропущенное, открытые вопросы |
| `/volna:skip <этап> <причина>` | пропустить этап своими словами; обычный пропуск — просто команда следующего этапа |
| `/volna:journal <текст>` | дописать запись в журнал |
| `/volna:checkpoint` | дописать журнал до восстановимого состояния — перед `/compact` |
| `/volna:off`, `/volna:on` | заглушить подсказки «Волны» до конца сессии и вернуть обратно |

Флоу — 13 этапов, `implement` и `advocate` крутятся циклом, пока адвокат не даст «чисто»
(цикл тоже идёт сам: находка адвоката и красный тест — это правка, а не вопрос человеку).
Уровни: `required` — только необратимое (`intake`, `deliver`, `close`), остальное `expected`
или `optional`. Коммит — не отдельный этап: он первый шаг доставки в `deliver`, и «да» на
доставку спрашивается один раз, а не трижды. Законный короткий путь:
`intake → analyze → close → cleanup` мимо `implement` («изменения кода не требуются»).
Отдельных команд «перейти к этапу» и «вернуться» нет: повторный вызов пройденного этапа
открывает **новую итерацию**, а прошлые записи журнала остаются как были. Ход, которым работа
отдаётся человеку, кончается одной строкой с готовой командой следующего шага **без параметров** —
её принимает `Tab` у поля ввода (команду с пробелом внутри подсказка не показывает); ход, за
которым работа продолжается сама, такой строки не содержит.

## Что где хранится

| Файл в рабочем репозитории | Назначение | Коммитится |
|---|---|---|
| `.env` | адреса, пути, путь к файлу с токеном | **нет** |
| `.volna/state.json` | указатель на активную задачу | нет |
| `.volna/journal/TASK-<id>.md` | состояние задачи: frontmatter и «Состояние» — источник правды | нет |
| `.volna/journal/logs/TASK-<id>.log.md` | лог итераций по этапам, append-only | нет |
| `.volna/project.md` | команды и конвенции команды | да |
| `.volna/knowledge/INDEX.md` | указатель записей опыта по этапам | да |
| `.volna/knowledge/<зона>/<slug>.md` | одна запись опыта — один короткий файл | да |
| `.volna/feedback.md` | замечания к самому флоу «Волны» с этапа `capture` | нет |

Два выхода у последнего этапа: знание о продукте, эталоне и инфраструктуре идёт в
`.volna/knowledge/` и **остаётся в проекте**, а замечание о самом флоу — этап мешал, правило
оказалось неверным, шаг систематически пропускался — в `.volna/feedback.md`, который **разбирается
при выпуске версии плагина**. Файл локальный, как журналы; нужно собирать замечания командой —
уберите его из `.gitignore`, формат тот же (шаблон — `feedback.template.md`).

Журнал состоит из двух слоёв, и они **разнесены по двум файлам**: `journal/TASK-<id>.md` —
переписываемая секция `## Состояние` (картина задачи сейчас: цель, установленное, решение,
отвергнутое, следующий шаг), `journal/logs/TASK-<id>.log.md` — append-only лог итераций по этапам.
Возврат к задаче в новой сессии — это чтение файла состояния целиком, он размером с экран; лог
открывается адресно и отвечает на вопрос «почему так вышло», а не «как обстоят дела». При
противоречии слоёв прав «Состояние».

Разнесены именно потому, что `Read` открывает файл целиком: на живой задаче лог доходит до
70 KB, и «не читай лог» как правило держалось на дисциплине, а теперь — на устройстве. Каталог
`journal/` остаётся плоским списком задач, логи лежат в его подкаталоге `logs/` — так их
покрывает то же правило `.gitignore`, что и журналы. Прежние раскладки читаются как есть: лог
рядом с состоянием и однофайловый журнал, где секции лежат в файле состояния.

Секретов в переменных окружения нет: в `.env` лежит **путь** к файлу с токеном, не сам токен.
Адреса серверов и машинные пути — только в `.env`, в репозитории «Волны» их нет.

## Что важно знать про правила

Правила этапов обкатаны примерно на пяти задачах с разным успехом — это **рабочий черновик**.
Правило мешает или неверно → правим его, а не обходим молча; этап, который систематически
пропускается, — повод упростить флоу. Механизм ревизии встроен в этап `capture`.

Предметные скиллы конкретного проекта «Волна» не поставляет: они остаются в рабочем
репозитории, а этапы используют их, если они есть — см.
[`docs/PROJECT-SKILLS.md`](docs/PROJECT-SKILLS.md).

## Ограничения

Отвергнуто **сознательно** — это не «пока не сделано», а решения, к которым не возвращаемся:
оркестратор агентов, worktree на задачу, параллельные задачи, свой web-UI, автоматический
сторож контекста по порогам, вендор-нейтральный слой требований, полноценный таймшит.
Всё это противоречит идее одной задачи в одном прогретом контексте.

Что «Волна» **не** умеет и о чём стоит знать заранее:

| Ограничение | Следствие |
|---|---|
| **одна задача за раз** | вторая задача параллельно не ведётся; переключение — через завершение задачи на `capture` или ручную смену активной |
| **гейт ловит только `git` из сессии** | коммит из IDE, GUI-клиента или соседнего терминала не проверяется — защита процессная, а не техническая |
| **один трекер** | `lib/tfs-client.mjs` написан под REST TFS / Azure DevOps Server; Jira, GitLab и прочее потребуют своего клиента |
| **Windows-first** | `install.ps1` рассчитан на PowerShell 5.1; hooks и CLI на Node кроссплатформенны, но проверялись на Windows |
| **правила писались под один проект** | этапы предполагают порт legacy и работу с TFS; нейтральность извлекать после задачи в другом проекте |
| **семантического поиска по журналам нет** | `/volna:recall` идёт по указателю знаний и `Grep` по журналам; индекс в KB отложен — до 20–30 журналов вектор шумит |
| **журналы не шарятся** | они в `.gitignore`; общее командное знание передаётся только через `.volna/knowledge/` |
| **шапка платится каждым сообщением** | ~0.5 с и ~100 токенов на сообщение; отключается отдельно — [`docs/INSTALL.md`](docs/INSTALL.md) |
| **обкатано на одном проекте и одном человеке** | все волны прошли живую работу, но на других командах и репозиториях не проверялись |
