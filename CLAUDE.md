# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за репозиторий

Маркетплейс из двух плагинов Claude Code (`.claude-plugin/marketplace.json`):

- **`volna`** (корень репозитория) — флоу задачи: скиллы `skills/volna-flow` и `skills/volna-journal`, команды `commands/*.md`, hooks `hooks/*.mjs`, CLI `bin/*.mjs`;
- **`volna-craft`** (`plugins/volna-craft/`) — только скиллы ремесленных правил, без hooks и кода.

Продукт здесь — **markdown-инструкции для модели плюс Node без зависимостей**. Сборки нет, `package.json` нет, все `.mjs` — ES-модули на голом Node. Правка текста в `skills/` или `commands/` меняет поведение так же реально, как правка кода.

Репозиторий ведут по самой «Волне»: в нём есть `.volna/` с профилем `трекер: нет`, `доставка: commit+push`, `закрытие: журнал`. Значит, при работе здесь активны команды `/volna:*` и гейт на commit.

## Команды

```bash
node hooks/test-hooks.mjs .      # hooks на синтетическом .volna во временном каталоге
node bin/test-volna-tfs.mjs      # CLI над TFS на поддельном клиенте, без сети
node bin/test-volna-jira.mjs     # CLI над Jira на подставном fetch, без сети
node bin/test-volna-wiki.mjs     # вика выводов на заглушках чтения, без ФС
node bin/test-volna-doc.mjs      # линт документации на синтетическом корпусе, без ФС
claude plugin validate .         # манифесты перед публикацией
```

Все пять наборов — собственный харнес `check(имя, условие, деталь)`: печатают строки `OK`/`FAIL`, в конце `ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ` и выход 1 при провале. **Фильтра по имени нет** — прогоняется весь файл целиком; отладка одной проверки делается временной правкой файла, а не флагом. `test-hooks.mjs` принимает первым аргументом корень «Волны» (обычно `.`) и порождает `.volna` в `%TEMP%/claude/volna-hooks-test`.

Отдельного линтера и форматтера нет.

### Локальная разработка плагина

Правки скиллов и команд подхватываются `/reload-plugins`. **Правки hooks — только с перезапуском сессии**: `/reload-plugins` перечитывает скиллы и команды, но hooks остаются те, что зарегистрированы при старте. Проверять исправленный hook в той же сессии бессмысленно — либо перезапуск, либо прямой прогон `node hooks/<hook>.mjs` из рабочей копии.

Подхватывать правки без переустановки плагина — junction из рабочего репозитория (`docs/INSTALL.md`, раздел «Локальная разработка»); одновременно junction и установленный плагин держать не стоит, команды задвоятся.

## Устройство

Три слоя, между которыми проходят все интересные связи.

**1. Инструкции для модели.** `skills/volna-flow/SKILL.md` — карта 13 этапов и правила автопрохода; `skills/volna-flow/stages/<этап>.md` — детали одного этапа (открывается только тот, который начинается); `skills/volna-flow/trackers/<трекер>/<этап>.md` — специфика конкретного трекера, открывается по строке профиля и никогда не читается проектом без трекера; `commands/<имя>.md` — точка входа человека, frontmatter с `description` и `argument-hint`.

**2. Hooks** (`hooks/hooks.json`): `session-start.mjs`, `preamble.mjs` (шапка на каждое сообщение), `gate.mjs` (блокирует `git commit` без записи журнала и `git push` вне `deliver`). Всё общее — в `hooks/lib/volna-state.mjs`: поиск `.volna`, парсер frontmatter, чтение `state.json` и журнала, список `STAGES`.

**3. CLI без сети в тестах.** `bin/volna-tfs.mjs` и `bin/volna-jira.mjs` — обёртки над `lib/tfs-client.mjs` / `lib/jira-client.mjs`; `bin/volna-wiki.mjs` — над `lib/wiki*.mjs`. Все три экспортируют `run(argv, deps)`, куда тест подставляет клиента, `fetch`, `log`/`err` — поэтому проверки идут без сети и без ФС. `lib/env.mjs` читает `.env` (уже заданная переменная окружения важнее файла).

### Инварианты, которые легко нарушить

- **Имя этапа живёт в четырёх местах разом:** файл `stages/<этап>.md`, значение `stage` во frontmatter журнала, команда `/volna:<этап>`, строка в таблице `SKILL.md`. Исключение одно: `intake` вызывается командой `/volna:task`.
- **Порядок этапов продублирован в коде** — массив `STAGES` в `hooks/lib/volna-state.mjs` даёт позицию `k/13` в шапке. Переставили этап в `SKILL.md` — правьте массив и проверки порядка в `hooks/test-hooks.mjs`.
- **Правило тишины hooks:** любая своя ошибка — тихий выход 0 (`runQuietly`), hook не имеет права ломать работу. Исключений два: намеренный гейт и сообщение о битой настройке (неизвестные ключи `state.json`) — о ней молчать дороже.
- **Профиль проекта — не «включить/выключить», а три состояния:** строка заполнена → работать по ней; плейсхолдер шаблона (`<нет|tfs|jira>`) → остановиться и спросить; секции нет вовсе → всё на месте (трекер, несколько репозиториев, эталон, полная доставка). Логика — `readProfile`/`isPlaceholder`/`hasTracker`.
- **`.volna` и `.env` ищутся вверх только до корня репозитория** (каталог с `.git`), не выше: чужая настройка соседнего проекта не подхватывается.
- **Секретов в `.env` нет** — там путь к файлу с токеном (`TFS_PAT_FILE`, `JIRA_TOKEN_FILE`). Ни в `.env`, ни в журнал, ни в вику значение токена не попадает.
- **Хранилище выводов — `.volna/wiki/`**; прежний `.volna/knowledge/` читается и переносится командой `volna-wiki migrate`. В текстах правил должно фигурировать `wiki`.
- **Переводы строк заданы `.gitattributes`:** `.mjs`/`.md`/`.json`/`.py` — LF, `*.ps1` — CRLF и UTF-8 с BOM (без BOM PowerShell 5.1 падает на кириллице). Инструмент, переписывающий файл целиком, легко ломает это молча.

## Конвенции этого репозитория

Полностью — в `.volna/project.md`; главное:

- версия правится в `.claude-plugin/plugin.json` **и** `.claude-plugin/marketplace.json` вместе с содержательной правкой, а не отдельным коммитом;
- сообщение коммита — одна строка `версия плагина <X.Y.Z>: <что сделано>`, **без трейлеров, в том числе без `Co-Authored-By`**; работа идёт прямо в `main`;
- поставили тег — сразу правьте строку версии в `docs/STATUS.md` тем же заходом;
- каждое решение по устройству плагина дописывается в `docs/DECISIONS.md` нумерованным пунктом: что наблюдалось → что сделано → что отвергнуто и почему; состояние решения (`предложено`, `снято в <версия>`) пишется словом в самом пункте, а `docs/STATUS.md` остаётся точкой входа в сессию;
- комментарии — одна строка «что делает (`<источник>`)», русский язык, ASCII-пунктуация (`->`, `-`, `"`), без номеров задач;
- имя проверки в тесте — утверждение о поведении (`check("push при mode: local: гейт молчит", ...)`); новый механизм без проверки не выпускается.

Замечания к самому флоу копятся в `.volna/feedback.md` (локальный, в `.gitignore`) и разбираются при выпуске версии — отсюда коммиты вида «разобраны накопленные замечания к флоу».
