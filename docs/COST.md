# Стоимость «Волны»

> Только измеренные цифры. Оценки и прикидки помечены явно — их нельзя цитировать как замер.
>
> **Все цифры ниже:** замер 01.08.2026, `volna` 0.1.30, `volna-craft` 0.1.0.
> Node v20.20.1, Windows 10, Claude Code с моделью Opus.
> Прежние срезы (0.1.5, 0.1.21) остались строками истории там, где по ним видно направление.

Зачем документ: решение «оставить шапку сессии или выключить», «ставить ли второй плагин»
принимается по цифрам. Без них спор про стоимость сводится к ощущениям.

---

## Из чего складывается стоимость сессии

| Слагаемое | Платится | Порядок |
|---|---|---|
| **always-on** — описания скиллов и команд в системном промпте | один раз за сессию | ~1.9k токенов |
| **on-invoke** — тело скилла при его вызове | каждый вызов | 0.2–6.9k токенов |
| **шапка** `UserPromptSubmit` | каждое сообщение | ~50–100 токенов (оценка, см. ниже) |
| **hooks как процессы** | каждое событие | 0 токенов, 0.42–0.50 с времени |
| **чтение журнала и знаний** | по ходу этапов | не измерено |

---

## Always-on: что висит в каждой сессии

Измерено `claude plugin details <плагин>@volna` — оценка харнеса, та же, что видит пользователь.

| Плагин | Компонентов | Always-on |
|---|---|---|
| `volna` | 24 (2 скилла, 22 команды) + 3 hook'а | **~1 179 токенов** |
| `volna-craft` | 6 скиллов | **~736 токенов** |
| **итого** | | **~1.9k токенов на сессию** |

**С 0.1.21 always-on практически не двигался:** ~773 (0.1.19, 15 компонентов) → ~1 173
(0.1.20, переход на команду для каждого этапа — плюс ~400) → ~1 173 (0.1.21) →
**~1 179 (0.1.30)**. Разница 0.1.21 → 0.1.30 — **шесть токенов**, при том что между ними:
объединение `commit` с `deliver` (минус команда), автопроход, локальный режим, разделение
журнала, профиль проекта и изоляция. Почти все эти правки шли в **тела** скиллов и команд, а
инвентарь считает `description`.

Прежняя запись здесь предсказывала после объединения `commit` с `deliver` около **~1 143**
вычитанием стоимости удалённой команды. Замер показал **~1 179**, то есть на 36 больше
предсказанного. **Чем именно набраны эти 36 — не выяснено**: правки описаний за восемь версий
никто не отслеживал покомпонентно, а прежней таблицы по компонентам для сравнения нет. Вывод
не в причине, а в методе — **вычисленную цифру нельзя ставить в один ряд с замеренной**, даже
когда арифметика выглядит очевидной.

**Переход на «команда на каждый этап» стоил ~400 токенов always-on** (0.1.19 → 0.1.20). Ожидание,
что `disable-model-invocation: true` уберёт эти описания из бюджета, **замером не подтвердилось**:
инвентарь считает этапные команды по ~30–50 токенов каждую, как и остальные. Флаг закрывает
вызов командой из модели, но её описание в always-on остаётся. Цена принята: 400 токенов на
сессию — это четыре-восемь шапок, а этап перестал набираться по памяти.

Hooks в инвентаре помечены `harness-only — no model context cost`: они исполняются харнесом
и в контекст не попадают. Контекст занимает только то, что hook напечатал (шапка — ниже).

## On-invoke: цена вызова

`volna` — платится, когда модель открывает скилл или пользователь набирает команду:

| Компонент | Always-on | On-invoke | Было в 0.1.21 |
|---|---|---|---|
| `volna-flow` | ~180 | **~7k** | ~5.4k |
| `volna-journal` | ~190 | **~3.1k** | ~3.8k (было ~6.2k в 0.1.31, см. ниже) |
| `doctor` | ~40 | **~3.5k** | ~2.5k (было ~4.6k в 0.1.32, см. ниже) |
| `init` | ~40 | ~1.4k | ~700 |
| `recall` | ~40 | ~990 | ~890 |
| `task` | ~30 | ~920 | ~390 |
| `checkpoint` | ~40 | ~910 | ~570 |
| `status` | ~40 | ~670 | ~550 |
| `skip` | ~30 | ~650 | ~580 |
| 12 команд этапов (`analyze` … `capture`) | ~30–50 каждая | ~270–570 | ~210–330 |
| `journal`, `off`, `on` | ~20–30 | ~190–370 | ~120–270 |

**Тела растут, и это осознанная цена.** С 0.1.21 к ним добавились: локальный режим, разделение
журнала на состояние и лог, профиль проекта, проверка изоляции. Дороже всего вышли три
компонента: `volna-flow` (+1.6k — профиль, автопроход, три состояния строки профиля),
`volna-journal` (+2.4k к 0.1.31 — два файла журнала, правила «Состояния», архив закрытой задачи) и
`doctor` (+2.1k — сверка скиллов и проверки по профилю). Платится это **при вызове**.

**Разгрузка `volna-journal` в `references/` (0.1.32) дала −50%: 6.2k → 3.1k**, замер инвентарём
до и после публикации. Тело ушло с 249 строк до 133; вынесены `layout.md` (устройство двух
файлов, раскладка, сборка идентификатора), `state.md` (потолок «Состояния», что в него не идёт,
архив закрытой задачи, вопросы чек-пойнта) и `time.md` (запреты по меткам и их последствия).
В теле остались формат секции лога, список подпунктов «Состояния», правило метки одной строкой
и правила записи — то, к чему обращаются **при каждой** записи.

Делить надо **по частоте обращения, а не по объёму**: вынесенное, если его читают на каждом
этапе, обходится дороже — два чтения вместо одного плюс лишний круг «прочитал скилл → понял, что
нужен ещё файл». Суммарный объём при этом вырос (249 → 337 строк вместе с `references/`):
в вынесенных файлах есть место для обоснований, которых в теле быть не должно.

**Та же операция на `doctor` (0.1.33) дала −24%: 4.6k → 3.5k.** Вынесен раздел «Сверка скиллов»
(50 строк из 149, треть файла) в `skills/volna-flow/references/skill-audit.md`; в команде остался
пункт с тремя условиями, когда файл вообще открывать — первое заведение проекта, новые скиллы
против прошлого прогона, явная просьба. В проекте без личных и проектных скиллов файл не читается
вовсе, а раньше эти 50 строк оплачивались каждым прогоном.

Выигрыш меньше, чем у `volna-journal` (−24% против −50%), и это ожидаемо: там выносилась половина
тела, здесь треть. Заодно проверено, что паттерн работает **и для команд**, а не только для
скиллов: `commands/` не поддерживает подкаталогов, но команда может указать файл внутри плагина —
так уже устроены 13 этапных команд, читающих `skills/volna-flow/stages/<этап>.md`.

Always-on от обеих разгрузок **не изменился** (~1 179) — инвентарь считает `description`, а он
не правился. Самое дорогое, что осталось: `volna-flow` ~7k — но он читается раз за контекст,
и в нём уже вынесены `autopass.md`, `duties.md` и `skill-audit.md`.

`volna-craft` не менялся с 0.1.0 — все шесть скиллов по ~120–130 always-on, on-invoke тот же:

| Скилл | On-invoke |
|---|---|
| `port-by-reference` | ~2.7k |
| `test-fixtures` | ~1.7k |
| `visual-compare` | ~1.6k |
| `test-style` | ~1.2k |
| `code-comments`, `commit-style` | ~1.1k |

Плюс детали этапа: `stages/<этап>.md` читается **по одному файлу на этап** — правило
«не загружать все» в `volna-flow` существует именно ради этой строки бюджета.

## Шапка сессии — единственное, что платится на каждом сообщении

Замер на **живом** журнале (локальная задача `260801-cost-remeasure`, этап `intake`, открытых
пунктов нет, ветки нет) и на синтетическом из теста (bug, `implement`, два открытых пункта, ветка):

| Величина | Живой журнал, начало задачи | Синтетический, середина работы |
|---|---|---|
| строк | **1** (бюджет — 20) | **3** |
| символов | **128** | **250** |
| в токенах | **~50** — оценка: кириллица ≈ 2.5 символа на токен, не замер | **~100** — оценка |
| худший случай при полном бюджете | ~1.8k символов ≈ ~700 токенов — оценка | |

`SessionStart` на том же живом журнале — **6 строк, 448 символов**, но платится он один раз
за сессию, а не каждым сообщением.

Практический смысл: диалог на 100 сообщений с типичной шапкой — порядка **5–10k токенов**
(оценка). Это сопоставимо со всем always-on обоих плагинов, и это главный кандидат на отключение,
если польза не проявится. Как выключить отдельно от остальных hooks — в
[`INSTALL.md`](INSTALL.md#hooks-что-делают-и-как-отключить).

Шапка молчит полностью, когда активной задачи нет или включён `/volna:off` — обычный чат
в репозитории с «Волной» не дорожает.

## Hooks: время, а не токены

Замер: 5 запусков подряд на живом `.volna` этого репозитория, среднее.

| Hook | Время на вызов | Разброс 5 прогонов |
|---|---|---|
| `preamble.mjs` | **421 мс** | 418–429 |
| `session-start.mjs` | **425 мс** | 419–432 |
| `gate.mjs` | **421 мс** | 416–424 |

Почти всё — старт процесса Node на Windows; сама работа (чтение двух файлов из `.volna` и, с
0.1.30, профиля из `project.md`) занимает единицы миллисекунд: чтение третьего файла в гейте на
времени не отразилось. Прежние замеры давали 420–440 и 490–495 мс на разных машинах, так что
рабочий диапазон — **0.42–0.50 с на событие**. `preamble` платится каждым сообщением,
остальные два — редкими событиями.

## Урок про описания

Сокращение `description` шести скиллов `volna-craft` с перечисления всех правил до «зона +
триггер вызова» уменьшило always-on плагина с **~1 166** до **~736** токенов — при том, что
на выбор скилла моделью это не повлияло. Правило: в `description` — зона и триггер,
перечисление запретов — в теле скилла, которое платится только при вызове.

## Что удешевляет работу

- **Один прогретый контекст вместо перезапусков.** Headless-рестарт заново оплачивает
  системный промпт, конвенции и схемы инструментов; `/compact` после чек-пойнта — нет.
  Экономия в токенах не измерена, оценки в документ не вносим.
- **KB-поиск вместо чтения файлов целиком** (`search_*` MCP-сервера проекта).
- **Знание = один короткий файл** в `knowledge/<зона>/` плюс указатель `INDEX.md`: этап
  читает секцию указателя и открывает названное, а не весь накопленный по теме опыт.
- **Детали этапа по одному файлу**, а не весь каталог `stages/`.

## Что не измерено

- реальный расход токенов на живой задаче от `intake` до `close` (нужен прогон с учётом);
- стоимость чтения журнала и записей знаний по ходу этапов;
- экономия `/compact` против перезапуска процесса — качественно очевидна, численно нет;
- стоимость шапки в токенах (сейчас — оценка из символов, не замер);
- цена самого профиля проекта: чтение `## Профиль` этапом идёт внутри уже открытого
  `project.md`, отдельной строкой бюджета не выделяется.

Появятся цифры — вносить сюда с датой и способом замера, оценки не смешивать с замерами.
