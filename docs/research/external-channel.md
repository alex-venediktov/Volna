# Исследование: вынос вопроса агента во внешний канал

> **Дата:** 26.07.2026. **Проверено на:** Claude Code 2.1.220, Windows 10, вход через claude.ai.
> Постановка задачи — в [`../STATUS.md`](../STATUS.md), раздел «Что осталось».

## Вердикт

**Своего универсального коннектора писать не надо.** Ключевая неизвестность (пункт 2
постановки — «можно ли вернуть ответ из внешнего канала в ждущую сессию, не перезапуская
процесс») закрыта: **можно, и это штатная функциональность Claude Code**, причём в трёх
независимых видах. Задача «Волны» сжимается с «построить коннектор» до «подключить готовое
и дописать правила», плюс одна маленькая необязательная деталь своими руками — односторонний
пуш «тебя спросили».

## Что нашлось

| Механизм | Направление | Готовность | Свой код | Ограничение |
|---|---|---|---|---|
| **Remote Control** | двустороннее: ведение сессии с телефона или браузера | research preview, все планы | **нет** | на Team/Enterprise включает Owner; транскрипт хранится на серверах Anthropic |
| **Channels** — готовые плагины Telegram / Discord / iMessage | двустороннее: чат-мост + relay подтверждений | research preview | **нет** | нужен Bun; на Team/Enterprise нужен `channelsEnabled`; переписка идёт через внешний мессенджер |
| **Channels** — свой канал (в т.ч. `ntfy.sh`, вебхук) | двустороннее | контракт описан | MCP-сервер на stdio | в preview свой канал грузится только через `--dangerously-load-development-channels` |
| **Hook `Notification`** | одностороннее: «тебя спросили» | стабильная функциональность | ~30 строк на Node | ответить из канала нельзя, только прийти к терминалу |

### 1. Исходящее — чем ловится «агент ждёт ответа»

Hook-событие **`Notification`** с матчерами: `permission_prompt`, `idle_prompt`,
`agent_needs_input`, `agent_completed`, `elicitation_dialog` и другими. На вход приходит
`notification_type` и `message`. Блокировать не может, текст в контекст не возвращает —
это чистый побочный эффект, ровно то, что нужно для отправки пуша. Таймаут по умолчанию
600 с, стоимость в контексте — ноль (как и у наших четырёх hooks).

Отдельно: **`Elicitation`** — событие на запрос ввода со стороны MCP-сервера, оно уже умеет
блокировать и подставлять ответ (`action`, `content`). Это запасной путь, если понадобится
перехватывать вопросы конкретного сервера.

### 2. Входящее — то, ради чего затевалось

**Remote Control** (`claude --remote-control`, `/remote-control`, `claude remote-control`).
Локальная сессия остаётся на машине, claude.ai и мобильное приложение — окно в неё. Флаг
присутствует в сборке 2.1.220 (`claude --help` его показывает). Мобильные пуши настраиваются
в `/config`: **«Push when actions required» — это буквально уведомление о вопросах и запросах
разрешений**, с ответом прямо с телефона. Ноль строк кода.

**Channels** — MCP-сервер, объявивший capability `claude/channel`, пушит события в открытую
сессию; они приходят модели тегом `<channel source="..." ...>`. Двусторонний канал добавляет
обычный MCP-инструмент `reply`. Отдельная возможность — **permission relay**
(`claude/channel/permission`): диалог подтверждения уходит в канал с пятибуквенным
`request_id`, человек отвечает `yes <id>` / `no <id>`, локальный диалог при этом остаётся
открытым и применяется тот ответ, который пришёл первым. Готовые плагины: Telegram, Discord,
iMessage, демо-канал fakechat.

Обе вещи — **research preview**: `--channels` и `--dangerously-load-development-channels`
в `claude --help` не показываются, синтаксис может измениться.

### 3. Форма адаптера, если делать своё

MCP-сервер на **stdio** (Claude Code запускает его подпроцессом), рантайм любой из
Node / Bun / Deno, единственная зависимость — `@modelcontextprotocol/sdk`. События шлются
через `mcp.notification({ method: 'notifications/claude/channel', params: { content, meta } })`;
ключи `meta` становятся атрибутами тега. Ответ обратно — обычный MCP-инструмент.
Вебхук-приёмник для `ntfy.sh` или CI укладывается в один файл.

Но: **в preview свой канал не попадает в allowlist**, и для команды это неприменимо —
каждому пришлось бы запускать `claude` с флагом `--dangerously-load-development-channels`.

### 4. Безопасность — здесь самое важное для нас

- **Прайваси перевешивает удобство.** Remote Control хранит транскрипт сессии на серверах
  Anthropic (для синхронизации между устройствами). У нас в рабочем репозитории — внутренние
  имена систем, адреса и постановки из трекера; решение о таком выносе принимает не
  разработчик. Channels держат всё локально, но переписка идёт через Telegram или Discord,
  то есть тоже наружу. Публичный `ntfy.sh` — тем более: туда уйдёт текст вопроса.
- **Инъекция промпта.** Любой негейтованный канал — вектор: кто дотянулся до эндпоинта, тот
  положил текст перед моделью. Контракт требует проверять **отправителя** (его id), а не
  комнату; Telegram и Discord решают это парой «сообщение боту → код → подтверждение в сессии».
- **Permission relay = право одобрять tool use.** Любой, кто может ответить в канал, может
  разрешить `Bash` и `Write` в вашей сессии. Это прямо противоречит нашему правилу «`--confirm`
  ставит человек»: удалённое «да» ничем не отличается от локального.
- Клиенты с 2.1.211 санируют `description` и `input_preview` перед отправкой (у нас 2.1.220).

### 5. Цена

Hook `Notification` — 0 токенов, порядка 0.5 с на событие (как остальные наши hooks, замеры
в [`../COST.md`](../COST.md)), и событий этих единицы за сессию, а не одно на сообщение, как
шапка. Канал добавляет в системный промпт строку `instructions` MCP-сервера и приносит
события тегом `<channel>` — платится по факту сообщений. Remote Control контекст не трогает
вовсе.

## Что это значит для «Волны»

1. **Коннектор не пишем.** Пункт «подключаемый универсальный коннектор» закрывается ссылкой
   на штатные механизмы: Remote Control для ведения работы с телефона, Channels для чат-моста.
2. **Своё остаётся ровно одно и необязательное** — hook `Notification` (матчеры
   `agent_needs_input`, `permission_prompt`, `idle_prompt`), отправляющий короткий пуш на
   произвольный вебхук: адрес в `.env`, по умолчанию выключено, тело — только тип события
   и первая строка вопроса, без содержимого работы. Это единственная часть, которая работает
   без preview, без Bun, без чужих серверов и на любом канале (self-hosted `ntfy`, внутренний
   бот, что угодно, что принимает POST).
3. **Правило во флоу.** Удалённое подтверждение необратимого (`commit`, `push-pr`, `close`,
   любая запись в трекер с `--confirm`) допускать только осознанно: relay даёт право одобрять
   tool use всем, кто в allowlist канала. Гейт «Волны» при этом остаётся — он проверяет запись
   в журнале, а не то, откуда пришло «да».

## Ограничения, которые надо принять до прототипа

| Что | Следствие |
|---|---|
| Remote Control и Channels — research preview | синтаксис флагов может измениться; в командную инструкцию писать рано |
| на Team/Enterprise оба выключены по умолчанию | нужен Owner: тумблеры Remote Control и `channelsEnabled` в admin-настройках claude.ai |
| готовые каналы требуют Bun | на этой машине `bun` не установлен |
| свой канал в preview — только под `--dangerously-load-development-channels` | для команды не годится, годится для эксперимента |
| Remote Control не работает с API-ключом и с чужим `ANTHROPIC_BASE_URL` | у нас вход через claude.ai, `ANTHROPIC_BASE_URL` не задан — условие выполняется |

Проверено на этой машине: Claude Code **2.1.220**, вход **oauth claude.ai**, организация
**WA AI**, роль **user** (значит, тумблеры включает не пользователь), `bun` **не установлен**,
`--remote-control` в `--help` **есть**, `--channels` не показан (ожидаемо для preview),
локальных managed-settings нет.

**Remote Control проверен на деле 26.07:** согласие дано, сервер зарегистрировался и вышел
в `Ready` с выданным идентификатором окружения — то есть **политика организации его не
блокирует**, тумблер Owner'а уже включён. Автоподключение при этом выключено
(`remote_control_at_startup: false`), Remote Control поднимается только явной командой.
Остаётся решение о данных: включив его, мы соглашаемся на хранение транскрипта сессии
на серверах Anthropic. Мобильные пуши о вопросах — отдельный переключатель в `/config`
(«Push when actions required»).

## Развилка — что прототипировать

| Путь | Стоимость | Что даёт | Чего требует |
|---|---|---|---|
| **A. Hook `Notification` → вебхук** | полдня, ~30 строк в плагине | одностороннее «тебя спросили» на телефон | ничего, кроме адреса в `.env` |
| **B. Remote Control** | час на попробовать | полноценный ответ и подтверждение с телефона | тумблер от Owner; согласие на хранение транскрипта у Anthropic |
| **C. Telegram-канал** | день | чат-мост и relay подтверждений | Bun, бот, `channelsEnabled`, переписка через Telegram |

Рекомендация: **A + B**. A мы контролируем целиком и она переживёт любые изменения preview;
B закрывает исходную задачу без единой строки кода, если организация разрешит. C имеет смысл
только если B окажется закрыт по политике, а вопросы всё равно надо отвечать удалённо.
