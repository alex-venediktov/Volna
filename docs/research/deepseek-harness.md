# Разбор: агентский харнес DeepSeek (`dsh`)

> **Дата:** 13.09.2026. **Изучено на:** [`deepseek-ai/deepseek-harness`](https://github.com/deepseek-ai/deepseek-harness),
> коммит `c291e79` от 10.09.2026 (релиз 0.1.5), MIT, developer preview.
> Рабочая копия снималась `git clone --depth 1` во временный каталог; в репозиторий «Волны»
> из неё ничего не попадает. Все пути ниже — пути внутри репозитория `dsh`.

## Вердикт

Прямых заимствований кода нет и быть не может: `dsh` — это **рантайм** (TypeScript, около
10 300 файлов, полсотни групп пакетов, свой агентный цикл, своё хранилище сессий), а «Волна» —
**свод инструкций поверх чужого рантайма**, Claude Code. Устройство `dsh` для нас нерелевантно
почти целиком.

Зато релевантна его **дисциплина письменного знания**. DeepSeek решает ту же задачу, что и мы:
как сделать, чтобы знание о проекте накапливалось в файлах, а не в голове и не в истории чата,
и чтобы модель это знание применяла. Их ответ подробнее нашего и в нескольких местах лучше.
Семь вещей стоит перенести, пять — отложить, шесть — сознательно не брать.

**Главное, что берём:** отдельный жанр «решение» с состоянием и обязательным списком отвергнутых
вариантов (разгружает разросшийся `STATUS.md`), отдельный жанр «постмортем» (почему процесс
пропустил дефект — это не то же самое, что решение), передача из пяти полей между частями работы,
явная фаза задачи с кодом блокировки, скилл о дисциплине прозы, бюджеты и ссылки как проверки,
обязательные разделы «что видит модель» и «чего не умеет».

## Что такое `dsh`

Открыт 13.08.2026. Девиз — **everything is a plugin**: модель-адаптер, реестр инструментов,
журнал сессии и сам агентный цикл смонтированы как плагины на мета-фреймворке
[Cordis](https://github.com/cordiverse/cordis). Привилегированного ядра, которое надо патчить,
нет: расширение — это ещё один плагин рядом, а регистрация — эффект, откатывающийся при
выгрузке (`docs/architecture.md`).

Собирается из **профилей** (`web`, `headless`, `sdk`, `sdk-minimal`, `acp`) и **бандлов** —
упорядоченных слоёв конфигурации; любую строку дерева можно заменить своим патчем. Запуск
один: `npx @deepseek-ai/dsh web`.

### Словарь, который стоит знать

| Термин | Что означает |
|---|---|
| **step** | один запрос к модели плюс вызванные им инструменты |
| **turn** | ход: ноль или больше шагов; открывается до первого принятого ввода и закрывается, когда ничего не осталось |
| **round** | внешняя итерация политики — раунд цели или одна попытка «свежего агента» |
| **seam** (шов) | заменяемая способность из трёх ролей: определение сервиса, поставщик, потребитель; неполный набор швом не считается |
| **session log** | append-only журнал событий; из него **выводится** вся история, которую видит модель |
| **goal** | долговременная цель сессии с фазами и потолком раундов |
| **Ralph loop** | цикл, где каждый раунд начинает свежий агент без наследования переписки |

Три плоскости событий: **durable** (факт пережил перезагрузку — в журнал), **`agent/*`**
(живое управление: очередь, статус, перехват запроса) и **capability** (политика на шве).
Главный инвариант всего проекта: **«model-visible ⟺ logged»** — всё, что попадает в запрос
к модели, обязано восстанавливаться из журнала, и это проверяется в рантайме.

Режимы работы (со страницы продукта): `standard` — полный набор инструментов, `code` — модель
пишет TypeScript, оркестрирующий инструменты, `minimal` — две функции для бенчмарков,
`creator` — инспекция и сборка своих конфигураций.

### Чем `dsh` отличается от «Волны» по природе

| | `dsh` | «Волна» |
|---|---|---|
| что это | рантайм агента | инструкции для модели плюс Node без зависимостей |
| чем принуждает | кодом: гейты, инварианты, типы | текстом на пути модели плюс четыре hooks |
| единица состояния | событие в журнале сессии | запись в журнале задачи и `state.json` |
| кто исполняет цикл | свой agent-loop | Claude Code |
| язык правил | TypeScript и markdown | markdown |

Отсюда фильтр для заимствований: **берём то, что живёт в markdown и в маленьком скрипте на
Node**; всё, что требует своего рантайма, не берём, даже если оно хорошее.

## Что берём: разбор по одному

Для каждой идеи названо **место в «Волне»** — без него правило не работает: это наш собственный
вывод `rules-rule-on-the-path` («верное правило, лежащее не на пути записи, не работает»).

### 1. Решение — отдельный файл с состоянием и отвергнутыми вариантами

**Что в `dsh`** (`.agents/notes/README.md`). Каждое нетривиальное изменение обязано принести
или обновить **Agent Note** в том же PR. Путь файла кодирует две оси —
`{состояние}/{класс}/ГГГГ-ММ-ДД-тема.md`, где состояние это `proposed` (предложено),
`implemented` (сделано) или `rejected` (отклонено, причина прямо в строке `Status:`), а класс —
одно из шести: `feature`, `bug-fix`, `simplification`, `architecture`, `process`, `testing`.
Скелет тела фиксирован и проверяется гейтом: у сделанного — `## Problem`, `## Decision`,
`## Alternatives considered`, `## Consequences`; у предложенного вместо решения `## Proposal`,
плюс `## Acceptance criteria` и `## Risks`. Раздел «отвергнутые варианты» **обязателен**:
решение, записанное без того, что оно победило, приглашает пересматривать себя заново. Отдельно
запрещено переписывать запись в **другое** решение: новое вытесняет старое, и они перекрёстно
ссылаются друг на друга. Централизованного указателя нет намеренно — дерево папок и есть
инвентарь.

**Что делать в «Волне».** У нас ровно тот же жанр — нумерованные решения в `docs/STATUS.md`
(«что наблюдалось — что сделано — что отвергнуто и почему»), но все 60 живут одним файлом
на 180 КБ. Файл перерос чтение целиком, а состояния у решения нет вовсе: предложенное,
принятое и отменённое выглядят одинаково.

Перенести стоит три вещи, не трогая сам жанр:

- **состояние решения** словом в самой записи: `предложено`, `принято`, `отклонено — причина`;
- **обязательный раздел «отвергнуто»** — в конвенции он у нас есть, но не проверяется ничем,
  и пустым встречается;
- **раскладка**: решение — отдельный файл (`docs/decisions/ГГММДД-тема.md` либо раздел вики),
  а `docs/STATUS.md` остаётся тем, чем заявлен в собственной шапке, — точкой входа в сессию:
  состояние работ и ссылки, а не полный корпус.

Класс решения (у них шесть) нам не нужен: наш аналог — поле `тип` записи вики, оно уже закрытый
список и проверяется кодом `K007`.

**Цена.** Разовый перенос 60 пунктов — работа на несколько заходов, её стоит вести частями.
Постоянная цена нулевая: `STATUS.md` и сейчас попадает в контекст только по ссылке.

### 2. Постмортем — отдельный жанр

**Что в `dsh`** (`docs/postmortem/README.md`). Постмортем **не** решение: дефект добрался туда,
куда не должен был, и интересна причина, по которой **процесс** его пропустил, а не однострочная
починка. Пишется при трёх признаках сразу: механизм неочевиден, причина системная (дыра
в тестах, инструментах, конвенциях, а не опечатка) и повторное выяснение дорого. Открывается
**резюме на тридцать секунд** — что сломалось, корневая причина простыми словами, почему
проскочило, устойчивый урок; дальше хронология, корневая причина и **добавленные страховки
со ссылками**. Штук всего четыре, с говорящими заголовками
(`0002-js-expression-disabled-filesystem-tools.md` — «инструменты файловой системы были
навсегда выключены литералом `!!js`»).

**Что делать в «Волне».** У нас этот жанр размазан: часть в решениях `STATUS.md`, часть
в выводах вики типа `побочный эффект`. Между тем именно он объясняет самые дорогие наши
истории — «гейт не срабатывал, потому что ключа `if` у `hooks.json` нет» (коммит `8ec3ac1`)
или «`/reload-plugins` не перечитывает hooks». Место: тип записи `постмортем`
в `.volna/wiki/SCHEMA.md` плюс требование первой строки-резюме и подпункта **страховка:** —
проверка, правило или место в тексте, которое теперь ловит этот класс дефектов. Этап — `capture`.

**Цена.** Один тип в схеме, абзац в `stages/capture.md`, одна проверка в `wiki-lint`
(постмортем без страховки — находка).

### 3. Передача из пяти полей

**Что в `dsh`** (`docs/glossary.md`, раздел «Ralph»). В Ralph-цикле каждый раунд начинает
**свежий** агент: ребёнок не получает ни переписки родителя, ни переписки предыдущего раунда.
Через границу проходят ровно две вещи — общий рабочий каталог и **один ограниченный структурный
отчёт**: статус, резюме, свидетельства, следующие шаги, текст блокера. Отчёт объявлен
**дополнением** к рабочему каталогу, а не заменой источника истины.

**Что делать в «Волне».** Это буквально наш `/volna:checkpoint` и переход между частями задачи,
но у нас форма передачи описана прозой, а не полями. Пять полей ложатся на существующую секцию
`## Состояние` почти без натяжки: `**сделано:**` (статус и резюме), `**следующий шаг:**`,
`**осторожно:**` (блокер). Не хватает одного поля — **свидетельства**: чем доказано, что
сделанное работает (строка вывода теста, путь к артефакту, номер прогона). Вместе с ним стоит
записать правило: чек-пойнт без свидетельств восстанавливает намерение, но не состояние.

Второе, что стоит забрать, — формулировку **«отчёт дополняет рабочее дерево, а не заменяет
его»**: у журнала та же роль по отношению к репозиторию, и её полезно сказать прямо
в `volna-journal`.

Заодно — мелочь из соседней подсистемы (`docs/subsystems/compaction.md`): сжатие контекста
у них обрамлено журналируемым замком `start` — `summary` — `end`, причём `end` пишется
последним намеренно, чтобы падение посередине оставляло **незакрытый замок**, а не ложную
отметку об успехе. У нас прерванный `/volna:checkpoint` неотличим от законченного; две строки
в журнале это чинят.

**Цена.** Строка в шаблоне журнала, абзац в `references/task-in-parts.md`, упоминание
в `commands/checkpoint.md`.

### 4. Фаза задачи и разоружение автопрохода

**Что в `dsh`** (`docs/subsystems/goal.md`). У цели четыре **устойчивые** фазы: `active`,
`paused`, `blocked`, `complete`. У блокировки есть **код** — стабильный kebab-case-идентификатор
для маршрутизации — и человеческое объяснение: «застряли» это не текст, а состояние с причиной,
которую можно найти поиском. Сверх фаз есть отдельное, **не сохраняемое** разрешение продолжать
(`armed` / `disarmed`), и оно **намеренно отсутствует в воспроизведении журнала**: после
возобновления сессии или ветвления автоматическая работа не начнётся, пока человек не разрешит
её заново. Плюс потолок раундов: цель не может крутиться вечно.

**Что делать в «Волне».** Два переноса, оба дешёвые:

- **фаза задачи** в `state.json` рядом с `active`. Сейчас там только «какая задача активна»,
  и задача, брошенная на полпути из-за вопроса к человеку, выглядит так же, как задача в работе.
  Осторожно: формат состояния закрытый — неопознанный ключ выключает сопровождение целиком
  (`STATE_KEYS` в `hooks/lib/volna-state.mjs`), так что добавление ключа это правка кода
  и проверок, а не только текста;
- **автопроход не переживает возобновление**. Сейчас правило автопрохода (`intake` → `capture`
  без остановок) действует одинаково и в свежем ходе, и после `/compact`, и после возврата
  к задаче в новой сессии. Правило `dsh` строже и разумнее: после восстановления контекста
  первый ход отдаётся человеку, дальше — как обычно. Место: `references/autopass.md`
  и `commands/checkpoint.md`.

Потолок раундов брать не стоит: у нас нет цикла, который крутился бы сам.

### 5. Дисциплина прозы: утечка рассуждений

**Что в `dsh`** (`.agents/skills/dsh-prose-standard/SKILL.md`,
`.agents/skills/dsh-trim-cot-leakage/SKILL.md`). Второй скилл целиком посвящён одному дефекту:
**текст написан с точки зрения сессии-автора, а не репозитория**. Единственная проверка:
сможет ли читатель на `HEAD`, без доступа к транскрипту, PR и черновикам, разрешить каждую
ссылку и проверить каждое утверждение? Таксономия из восьми классов: мёртвые ссылки
на артефакты сессии («решение 7», «пункт C2»), точка зрения PR («в этом PR», «предыдущий
коммит»), повествование об изменении («раньше», «теперь уже нет»), хореография ревью
(«отклонено на ревью»), оправдания перед рецензентом («приведение безопасно, ведь…»), пересказ
потока управления, хеджи («пока, наверное, хватит») и обрывки рабочего языка автора. Отдельно
перечислено, что утечкой **не** является: ссылки на задачи, обоснования подавленных проверок,
измеренные границы («измерено: 512 вложений ≈ 0,15 с»), контрфактические формулировки
(«без X произойдёт Y»). Первый скилл добавляет правило сохранения: перед сокращением выписать
все утверждения абзаца — актор, условие, порядок, модальность, отрицательную гарантию,
владение, побочный эффект — и сократить так, чтобы ни одно не пропало; меньше слов само
по себе не улучшение.

**Что делать в «Волне».** Это прямое продолжение `volna-craft:code-comments` («одна строка:
что делает (откуда)», без истории итераций и номеров задач), но у нас правило ограничено
комментариями в коде, а течёт в первую очередь **вика и `STATUS.md`** — их пишет модель
по итогам сессии. Уместен отдельный скилл `volna-craft` с той же единственной проверкой
и нашей таксономией; вызывать — на `capture` перед записью вывода и при правке `docs/`.

**Цена.** On-invoke скилл; на пути `capture` — одна строка вызова.

### 6. Гейты вне вики: ссылки и бюджеты

**Что в `dsh`** (`scripts/verify-*.ts`, `docs/AGENTS.md`). Около двадцати механических проверок
документации: `verify-md-links` (битые файлы и мёртвые якоря), `verify-doc-budgets` (потолок
слов на документ из манифеста `scripts/doc-budgets.manifest.json`), `verify-agent-note-format`
и `verify-agent-note-classification`, `verify-package-readme-model-experience`,
`verify-package-readme-limitations`, `verify-skill-invocation-metadata`. Ценно не количество,
а **порядок действий при красном бюджете**: сначала перенести содержимое туда, чей это предмет;
затем сократить то, что принадлежит этому документу; и только потом поднять потолок, обосновав
правку манифеста. Там же сказано: потолок — ограждение, а не цель сокращения, а слишком низкий
потолок это баг бюджета.

**Что делать в «Волне».** Для вики у нас это уже есть — `volna-wiki lint` с кодами
`K001`-`K020`, включая бюджет строк `K010`. Вне вики не проверяется ничего: ни ссылки
в `skills/`, `commands/` и `docs/`, ни объём файла этапа. При этом цена текста этапа прямая
и измеренная (`docs/COST.md`), а переименование команды задевает вику (наш вывод
`plugin-rename-touches-wiki`).

Сделать стоит две подкоманды того же инструмента:

- **ссылки**: проход по всем `.md` репозитория. Одна ловушка известна заранее: три «битые»
  ссылки, которые сейчас в репозитории есть, — это **примеры внутри кода** (в тексте вывода
  вики и в `STATUS.md` показан образец локатора, в `docs/reference/tfs-rest.md` — образец
  картинки markdown). Проверка обязана пропускать содержимое код-спанов и блоков, иначе
  родится красной;
- **бюджеты**: манифест «файл — потолок» для `skills/volna-flow/stages/*.md`, `commands/*.md`
  и `SKILL.md`, с тем самым порядком «перенести, сжать, поднять».

**Цена.** Один файл в `lib/`, подкоманда в `bin/volna-wiki.mjs`, проверки
в `bin/test-volna-wiki.mjs`.

### 7. «Что видит модель» и «чего не умеет»

**Что в `dsh`** (`docs/cookbook/adding-a-package.md`,
`scripts/verify-package-readme-model-experience.ts`). У README каждого пакета фиксированный
набор разделов, и два из них проверяются гейтом: **Model Experience** — что именно видит модель
(текст инструмента, его схема, формулировки результатов и диагностик) — и **Known Limitations
and Deferred Work** — чего пакет не умеет и что отложено. В скилле ревью то же вынесено
в обязательный пункт: инспектировать точные подсказки, схемы инструментов, результаты
и диагностику, которые получает модель, во всех затронутых режимах.

**Что делать в «Волне».** У нас **весь продукт** — это то, что видит модель, и при этом раздела
«что видит модель» нет ни у одной команды и ни у одного скилла. Практический эффект: правки
в `commands/*.md` и `stages/*.md` оцениваются на глаз, «читается ли», а не «что из этого дойдёт
до модели в момент действия». Минимум: у каждой команды строка «в контекст попадает: …»,
у каждого скилла раздел «чего не делает» (в `volna-craft` он местами есть в виде запретов,
в `volna-flow` его нет). Ограничения полезнее всего писать рядом с механизмом: половина наших
инвариантов собрана в `CLAUDE.md` — в одном месте и вдали от кода, которого касается.

**Цена.** По две-три строки на компонент разово; дальше — правило на `capture`.

## Что откладываем

- **Страж повторов** (`packages/guard/repeat-tool-reminder`). Советует, а не блокирует; пороги
  3, 5 и 8 одинаковых вызовов подряд, счётчик сбрасывает реплика человека, `todo_write`
  из подсчёта исключён. У «Волны» есть куда это положить — hook на `PostToolUse`, — но нужен
  надёжный признак топтания и своя проверка, а польза пока не измерена.
- **Спилл больших выводов** (`docs/subsystems/spill.md`). Текст сохраняется дословно, модель
  получает локатор и подсказку, как его достать. Для нас это правило без кода: дамп задачи
  трекера или длинный лог — в файл, в журнал — путь. Откладывается потому, что задевает
  `.gitignore` и гигиену временных файлов, а это отдельный заход.
- **Объём правки как основание для выбора проверок** (`pnpm run change-scope`,
  `.agents/skills/dsh-pre-push-checks/SKILL.md`). Правило сформулировано жёстко: никогда
  не запускать полный набор по умолчанию и не повторять ради коммита уже прошедшую проверку.
  У нас четыре набора и ручной выбор; правило «`hooks/` — `test-hooks.mjs`, `bin/` и `lib/` —
  свой тест, тексты — линт документации» стоит записать, но сначала должен появиться сам линт
  документации (идея 6).
- **Два флага вызываемости скилла** (`docs/subsystems/skills.md`): `modelInvocable`
  и `userInvocable` независимы, поддерживаются все четыре сочетания, метаданные проверяются
  гейтом. В Claude Code это `disable-model-invocation` и `user-invocable` во frontmatter.
  У «Волны» часть скиллов человеку вызывать незачем — расстановка флагов уберёт их из
  человеческого каталога. Дёшево, но требует замера: каталог скиллов оплачивается в always-on
  (`docs/COST.md`).
- **Замороженный архив записей** (`.agents/skills/dsh-archive-agent-notes/SKILL.md`). Запись
  архивируется, когда решение доведено **и** его обоснование вряд ли будет руководить будущей
  работой; после запечатывания она заморожена — не править, не переводить, не считать
  источником текущего поведения, целостность держит манифест хешей. Отдельно: не архивировать
  под квоту, длина не критерий. Вике «Волны» (53 записи) это пока не нужно, но правило стоит
  помнить к моменту, когда `wiki-lint` начнёт ругаться на объём разделов.

## Что сознательно не берём

- **Микроядро «всё — плагин», профили и бандлы.** Наше ядро — Claude Code, и оно уже устроено
  так: плагин, скиллы, hooks, команды. Второй слой композиции поверх чужого рантайма добавит
  только путаницу.
- **Инварианты как рантайм-реестр** (`docs/subsystems/invariants.md`). Идея сильная: проверка
  засчитывается, только если сравнивает **независимо полученные наблюдения**, которые могут
  разойтись; проверки «сервис существует» и «метод есть» объявлены невалидными. Но исполнять
  их у нас негде. Взять стоит не механизм, а критерий, и ему место в `volna-craft:test-style`:
  проверка, которая не может упасть, проверкой не является.
- **Workflow-скрипты и команды агентов** (`docs/subsystems/workflow.md`,
  `docs/subsystems/agent-team.md`). Модель пишет скрипт, запускающий подагентов пачками;
  у команд есть ростер, доска задач и почтовый ящик. «Волна» этот вопрос уже решила в другую
  сторону: подагент — чтение внутри этапа, а не ветвь флоу (коммит `87b4354`); ветвление флоу
  ломает журнал и порядок этапов.
- **Расписания, вебхуки, фоновые задания.** У Claude Code есть свои, и «Волна» намеренно
  не строит оркестратор: решения принимает человек.
- **Полнотекстовый индекс сессий** (`docs/subsystems/session-query.md`). `/volna:recall`
  закрывает ту же потребность поиском по журналам и вике, без SQLite и без индексации. Одна
  деталь всё же полезна: `dsh` классифицирует каждое событие журнала как `current`, `shadowed`
  (вытеснено сжатием) или `log-only`. Наш аналог — отличать в журнале действующее от уже
  пересмотренного; сейчас это держится на переписывании секции «Состояние».
- **Двуязычные пары с хешем соответствия.** Каждый документ `dsh` имеет китайского близнеца,
  парность проверяется гейтом, а перевод запускается только по явной просьбе человека.
  «Волна» одноязычна, и это осознанно.

## Где «Волна» и `dsh` сошлись независимо

Полезно не меньше заимствований: эти решения приняты нами раньше и подтверждаются чужим опытом.

| Правило `dsh` | Наш эквивалент |
|---|---|
| «model-visible ⟺ logged»: всё, что видит модель, восстановимо из журнала | журнал задачи как единственный источник восстановления контекста в новой сессии |
| «misconfiguration fails loud»: неверная настройка падает громко, молчаливый пропуск запрещён | неопознанный ключ `state.json` называется вслух — единственное исключение из правила тишины hooks |
| один дом для факта: у каждого утверждения ровно один владелец, в остальных местах ссылка | правило дубля в `wiki-lint` (`K012`) и таблица «что где искать» в `CLAUDE.md` |
| standing orders в корневом `AGENTS.md`: правило в одну-три строки там, где на него смотрят | наш вывод `rules-rule-on-the-path`: правило действует только там, куда смотрят в момент действия |
| мягкое ведение: plan mode объявлен soft guidance, страж повторов советует, а не блокирует | «Волна» подсказывает, а не блокирует; единственный жёсткий гейт — коммит без записи журнала |
| скиллы как процессы: ревью, подготовка к push, дисциплина прозы, архивация записей | `volna-craft` и команды `/volna:*` |

## Как перепроверить

```sh
git clone --depth 1 https://github.com/deepseek-ai/deepseek-harness.git
```

Порядок чтения, если проверять выводы этого документа (около часа):

1. `.agents/notes/README.md` — жанр «решение», состояния, обязательные разделы (идея 1);
2. `docs/postmortem/README.md` — жанр «постмортем» (идея 2);
3. `docs/glossary.md` — словарь, Ralph handoff, фазы цели (идеи 3 и 4);
4. `.agents/skills/dsh-trim-cot-leakage/SKILL.md` — таксономия утечки рассуждений (идея 5);
5. `docs/AGENTS.md` — тиры документации, бюджеты, список признаков «слопа» (идея 6);
6. `AGENTS.md` в корне — как выглядят standing orders на 1950 слов;
7. `docs/architecture.md` — устройство целиком, если нужен контекст.

Всё, на что ссылается документ, лежит в этих семи файлах и в `docs/subsystems/`.
