# Подвохи MCP-сервера task-tracker

Что стоило времени при написании `lib/tt-client.mjs`. Проверено на живом сервере (Streamable HTTP,
`http://<хост>:8113/mcp`) и по его исходнику `tracker/mcp_tools.py` в октябре 2026.

## Сессии нет: каждый вызов - отдельный POST

`initialize` не отдаёт заголовок `Mcp-Session-Id`, и `tools/call` проходит без него, первым же
запросом. Клиенту не нужен SDK MCP: POST JSON-RPC голым `fetch`.

```
curl -X POST http://<хост>:8113/mcp -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" -H "X-Project: <проект>" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"list_projects","arguments":{}}}'
```

`Accept` называет оба типа, как велит спецификация транспорта Streamable HTTP. Ответ этого сервера
приходит обычным JSON, но транспорт вправе ответить и потоком SSE: тогда сообщение - в строке
`data:`. Клиент разбирает оба вида.

## Ошибка инструмента - поле, а не код HTTP

Отсутствующая задача, занятый id, неизвестный статус - всё это HTTP **200** с `isError: true` и
текстом в `content[].text` (`Error executing tool get_task: задачи #999999 нет`). Проверка
`res.ok` такую ошибку пропускает как успех.

Удачный ответ несёт результат дважды: в `structuredContent.result` и тем же JSON строкой в
`content[].text`. Читать первое; второе - запасной путь.

## Недоступный сервер висит, а не отказывает

Адрес в сети, где хоста нет, не отвечает отказом: соединение ждёт, пока не кончится терпение
клиента. Быстрый отказ (`ECONNREFUSED`) бывает только тогда, когда хост есть, а службы на нём нет,
либо сети нет вовсе. Поэтому у каждого запроса - `AbortSignal.timeout` (`TT_TIMEOUT_MS`, 5000 мс).

## Id один на весь сервер

Задачи всех проектов лежат одним каталогом: `create_task` с `task_id`, который уже есть **в любом
проекте**, отвечает «id уже занят». Номер без `task_id` - наибольший числовой id по всему серверу
плюс 1. Отсюда правило «Волны»: N в `feature-N` - наибольший среди голых номеров и id с префиксом
вида **по всем проектам** плюс 1 (`list_projects`, затем `list_tasks` по каждому), а занятый в
промежутке id - повод посчитать заново.

Id - латиница, цифры, `-` и `_`, до 64 знаков. `/` не принимается: ветка `feature/3_slug` из id
собирается, а не совпадает с ним.

## Чего у сервера нет

- **типа задачи** - есть теги; вид для флоу берётся из префикса id, затем из тега `bug`/`research`;
- **родителя и связей** - ребёнок ссылается на родителя строкой в постановке, родитель на ребёнка -
  комментарием;
- **часов, оценки, исполнителя** - `time` и `estimate` в `volna-tracker` отвечают кодом 4;
- **удаления** - ненужную задачу переводят в `done` с комментарием;
- **частичной правки постановки** - `update_task` заменяет переданное поле целиком: дописать абзац
  значит прочитать `get_task`, склеить и записать.

## Свой проект - заголовок

`X-Project` называет проект подключения: без аргумента `project` инструменты работают в нём.
`list_tasks` без заголовка и без `project` отдаёт задачи всех проектов - клиент «Волны» заголовок
шлёт всегда, а чужой проект называет аргументом.
