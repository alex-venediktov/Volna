## Архитектурные решения (основа всего остального)

1. **«Волна» не может быть MCP-сервером.** MCP пассивен: не инжектирует промпты, не видит
   событий сессии и заполнения контекста. Поэтому разделение: флоу → skills + команды + hooks;
   состояние → markdown-файлы; интеграции и семантический поиск → MCP/CLI на периферии.
2. **Автоинъекция контекста — только hooks** (`UserPromptSubmit`). CLAUDE.md статичен, скиллы
   вызываются по решению модели, MCP-промпты — человеком. Шапка сессии — жёсткий бюджет
   ≤20 строк, иначе она × каждое сообщение съедает больше, чем экономит.
3. **Три уровня строгости** вместо «обязательно/необязательно»: `required` (гейт hook'ом,
   только необратимое), `expected` (напоминание, пропуск требует причины в журнал),
   `optional` (упоминание). По умолчанию — `expected`.
4. **Источник правды о задаче — журнал** (`.volna/journal/TASK-<id>.md`, YAML-frontmatter).
   `state.json` — только указатель на активный журнал. Дублировать состояние в двух местах
   нельзя: разойдётся.
5. **Дешёвый контекст как требование.** Один прогретый контекст вместо перезапусков процесса
   (headless-рестарт заново оплачивает системный промпт, конвенции и tool-схемы),
   `SKILL.md` ≤100 строк с деталями в отдельных файлах, KB-поиск вместо чтения файлов целиком,
   `/compact` после чек-пойнта вместо рестарта.
6. **Отвергнуто сознательно:** оркестратор, worktree на задачу, параллельные задачи, свой
   web-UI, автоматический сторож контекста по порогам, вендор-нейтральный слой требований,
   полноценный таймшит. Это противоречит идее одной сессии и дешёвого контекста.

**Влито по итогам прогона (PR #1):**

- **знание = один файл в каталоге зоны** (`knowledge/<зона>/<slug>.md`, 10–15 строк) вместо
  файла-на-тему: читается файл целиком, поэтому крупная тема тянула в контекст весь накопленный
  по ней опыт;
- **указатель `knowledge/INDEX.md`** с секциями по этапам — этап читает свою секцию и открывает
  названные записи, каталог целиком не читает;
- в `plan` — требование установить **компонент, который реально рендерит экран** (по импортам и
  роутеру, а не по совпадению имени файла с названием экрана);
- визуальная сверка — с работой без эталонного изображения.

Доведено следом (иначе влитое не работало бы у нового человека): шаблон
`knowledge-index.template.md`, создание `INDEX.md` в `install.ps1` и `/volna:init`, чтение
секции указателя на `plan`, `implement`, `unit-tests`, проверка расхождения указателя с файлами

## Принятые решения

1. **Журналы не коммитятся** — в `.gitignore` рабочего репозитория: `.volna/state.json`,
   `.volna/journal/`, `.volna/project.local.md`. Шарятся `.volna/knowledge/` и `.volna/project.md`.
2. **Сначала под один проект**, без слоёв абстракции: этапы написаны прямо под delphi-порт и
   TFS. Нейтральность извлекать после задачи в другом проекте.
3. **Правила этапов — черновик**; `required` только для необратимого (`intake`, `commit`,
   `push-pr`, `close`), остальное `expected`/`optional`; ревизия правил — часть этапа `capture`.
4. **Коммиты без трейлеров**, включая `Co-Authored-By` — переопределение общего поведения,
   прописано в `stages/commit.md` и скилле `commit-style`.
5. **Порядок трекера для бага**: задача-фикс создаётся на `push-pr` **до** push (иначе в PR
   попадёт номер бага); статусы меняются только на `close`, каждое изменение — отдельным
   подтверждением; ветка «изменений кода нет» — полноценный путь без PR и без пустого коммита.
6. **Для багфикса нужен тест, который падал бы до правки**, либо объяснение, почему такой
   невозможен.
7. **Никаких внешних зависимостей от других репозиториев.** Что было нужно — перенесено сюда.
8. **Публичный репозиторий = только процессная часть.** Имена внутренних систем, адреса и пути
   не попадают: приватное — в `.env`, предметные скиллы — в рабочем репозитории.
9. **Установка — штатным плагином, а не своим CLI.** Бутстрап-CLI (как у spec-kit на `uv`)
   оправдан мультиагентностью, а у нас один агент. Свой код в установке — только `install.ps1`.
10. **Управляющий промпт вне репозитория.** `docs/PROMPT-volna-system.md` — внутренний
    черновик; его содержательная часть перенесена в этот файл, ссылок на него в публичных
    документах нет.

### W3 — интеграции ✅ написана, ждёт проверки на живой задаче

| Артефакт | Что внутри |
|---|---|
| `bin/volna-tfs.mjs` | `check`, `get`, `query`, `comment`, `time`, `link-pr`, `attach`, `state`. Чтение свободно, **любая запись только с `--confirm`**: без флага команда печатает, что собиралась изменить, и выходит с кодом 1 |
| `lib/env.mjs` | чтение `.env` без зависимостей и без флага `--env-file`; заданная переменная окружения важнее файла; поиск вверх по дереву |
| `commands/recall.md` | поиск по указателю знаний → записям → журналам → KB-серверу; пустой результат — законный ответ, выдумывать «прошлый опыт» запрещено |
| `bin/test-volna-tfs.mjs` | 52 проверки на поддельном клиенте: ни одна пишущая команда без `--confirm` не делает ни одного вызова |

Подключено в флоу: `intake` зовёт `get` за постановкой, `close` — `state`/`time`/`attach`/`link-pr`
с подтверждением на каждое изменение, `doctor` — `check` для диагностики доступа.

Решения по ходу:
- **`link-pr` вешает гиперссылку, а не artifact-ссылку**: artifact-URI на PR
  (`vstfs:///Git/PullRequestId/...`) не собрать из URL без id проекта и репозитория, а
  гиперссылка работает всегда и в задаче выглядит так же;
- **`time` по умолчанию прибавляет** к уже списанным часам (читает текущее значение),
  `--set` заменяет: списание времени по этапам иначе затирало бы предыдущее;
- **`state` предупреждает про TF401320**: правила перехода состояний требуют своих полей, и
  ошибка выглядит как «нет прав», хотя дело в незаполненном поле.

**Отложено осознанно:** индекс журналов и знаний в KB-сервере (`search_journal`) — до 20–30
журналов вектор шумит, `Grep` по номеру и ключевым словам точнее. Второй MCP-сервер не поднимаем.
