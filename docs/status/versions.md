# Волна — история версий

> Что вошло в каждую версию плагина, новое сверху. Точка входа в сессию —
> [`../STATUS.md`](../STATUS.md): там строка «Последнее обновление» называет последнюю версию,
> а запись о ней дописывается сюда в начало, перед прежней. Решения — по номеру в
> [`../DECISIONS.md`](../DECISIONS.md).

версия плагина 0.1.69: тексты этапов на контракт `volna-tracker` - общий слой
`trackers/<этап>.md` (команды, статусы по смыслу, общие правила записи), в `trackers/<трекер>/`
только специфика, `doctor` и `recall` зовут `volna-tracker` - решение 92;
версия плагина 0.1.68: шлюз `task-tracker` под контракт `volna-tracker` -
клиент MCP по HTTP с таймаутом и ошибкой по `isError`, id `<префикс>-<N>` с номером по всему
серверу, шапка узнаёт `feature-12`, блок `TT_*` в `init` и `doctor`, файлы `trackers/task-tracker/` -
решение 91;
версия плагина 0.1.67: общий CLI трекера `volna-tracker` -
шлюз по строке `трекер`, статус по смыслу с именами из секции `## Статусы трекера`,
`capabilities`, код 4 «шлюз не умеет» - решение 90;
версия плагина 0.1.66: приём задачи по ссылке на страницу -
`/volna:task <url>` ведёт локальную задачу, ссылка идёт в `source`, текст постановки со страницы -
в журнал дословно, непрочитанная страница - останов с просьбой о тексте - решение 87;
версия плагина 0.1.65: части переведены на детей -
правила частей убраны из текстов, `/volna:children-run` вместо `/volna:parts-run`,
`volna-task migrate` переводит журнал с частями на детей, hooks читают старые журналы и предлагают
перевод - решение 86, снимает решения 57 и 63, часть 6 из 6;
версия плагина 0.1.64: дети в трекере - на `/volna:split`
у задачи трекера дети заводятся дочерними элементами TFS или Jira (`volna-jira create`,
`volna-task add --tracker`), родитель без своего `deliver` закрывается ветвью А без задачи-фикса,
часы без двойного счёта - решение 85, часть 5 из 6;
версия плагина 0.1.63: приёмка родителя - `close` задачи
с детьми проверяет её критерии на целом, провал приёмки встаёт новым ребёнком, `volna-task done`
закрывает и корень дерева - решение 84, часть 4 из 6;
версия плагина 0.1.62: очередь детей - `volna-task done`
возвращает работу родителю, `next` берёт следующего ребёнка по порядку, незакрытые задачи видны
в начале сессии и в `/volna:status` - решение 83, часть 3 из 6;
версия плагина 0.1.61: разделение на детей - `/volna:split`,
`bin/volna-task.mjs` заводит журналы детей с обеими ссылками и передаёт ребёнку работу, при
планировании родитель без своей работы, по ходу дети встают после доставки задачи - решение 82,
часть 2 из 6;
версия плагина 0.1.60: задача-узел - поля журнала
`children` и `status`, дерево задач в шапке, в начале сессии и в `/volna:status`, статусы детей
читаются из их журналов - решение 81, часть 1 из 6;
версия плагина 0.1.59, `volna-craft` 0.2.2: инструкции
сверены с рекомендациями для Opus 5 / 5.5 - адвокат называет все находки с серьёзностью и
повторяет проход только по диффу правки, проверку не отдают подагенту, `code-comments` главнее
умолчания харнеса - решение 80;
версия плагина 0.1.58: разобраны накопленные замечания
к флоу из пяти источников - правило дописано туда, где его читают: `advocate` на задаче без кода,
`git add -A` против решения «это не коммитим» (`plan` и `deliver`), локальный файл-артефакт на
`visual`, правка «по всем X» через перечисление на `implement`, запрет полного прогона тестов
в шаблоне `project.md`. Метки времени вынесены в код: hook `stamp-guard.mjs` называет метку,
ушедшую вперёд часов, в том же ходе. Маршрут вики перестал терять короткие акронимы - решение 79;
версия плагина 0.1.57: `/volna:parts-run` - прогон
остатка частей подагентами, по одной, до первой развилки и без коммитов; способ исполнения
(заходами или прогоном) выбирает человек на `spec` - решение 63;
версия плагина 0.1.56: состав и остаток частей считает
код - `partsProgress` в `hooks/lib/volna-state.mjs`; шапка хода печатает счёт, `SessionStart`
и `/volna:status` - карту частей целиком, блок «карта частей» обязателен на `spec`, `close` части
и `cleanup` с остатком - решение 62;
версия плагина 0.1.55, `volna-craft` 0.2.1: раздел
«Чего этот скилл не делает» дописан всем семи ремесленным скиллам - охват практики «граница
компонента названа» был неполным;
версия плагина 0.1.54: перенято семь практик из разбора
`deepseek-harness` - свидетельства и замок чек-пойнта, тип записи «постмортем», линт документации
`/volna:doc-lint`, фаза задачи и разоружённый возобновлением автопроход, скилл `prose-standard`,
строка «Не делает» у команд, корпус решений вынесен в [`DECISIONS.md`](../DECISIONS.md) - решение 61;
разбор чужого агентского харнеса - см. [`research.md`](research.md), раздел «Исследование: агентский харнес DeepSeek»;
