# Этап 8 · unit-tests — тесты · expected

## Что покрывать
- **Эталонный (характеризационный) тест на каждое состояние** `mirror` × `rotate` — состояний
  без теста не остаётся. Это правило родилось из реальных расхождений.
- Ветви, затронутые правкой: боковые профили, клапаны, ранние выходы.
- Для багфикса — тест, который **падал бы до правки**. Если такой тест написать нельзя,
  сказать почему (в журнал).

## Конвенции
Оформление — скилл `test-style` (имя как утверждение о поведении, обязательный
doc-комментарий, диагностические леса не коммитим); фреймворк, регистр имён и библиотека
сериализации — `.volna/project.md`. Данные — из оффлайн-фикстур (этап `fixtures`), не из живой БД.

Перед написанием тестов — секция `unit-tests` в `.volna/knowledge/INDEX.md`: открыть записи по
предмету задачи (что уже оказывалось непокрытым). Каталог целиком не читать.

## Прогон
Команды из `.volna/project.md`: полный прогон и, если есть, отдельный фильтр эталонных тестов.
Тест упал → это находка, а не повод ослабить тест. Правится код или, если ожидание в тесте
оказалось неверным, — исправляется ожидание **с обоснованием в журнале** (ссылка на строку
Delphi, а не «так проходит»). Красный тест — не развилка: **новая итерация `implement` открывается
сразу**, в том же ходе, команды на неё не ждём. Останов — только если непонятно, что верно
(СТОП-критерий).

## DoD
Новые тесты есть, все тесты проходят, вывод прогона зафиксирован в журнале. Тесты попали в
рабочее дерево (на `deliver` перед коммитом проверяется, что untracked не осталось).

## Типичные ошибки
- Один тест на `mirror=false, rotate=0` и «остальное аналогично».
- Ослабить ожидание, чтобы тест позеленел.
- Написать тест, который проходит и на старом коде.
- Забыть новый файл теста — он не дойдёт до PR и ревью.
