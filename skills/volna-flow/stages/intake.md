# Этап 1 · intake — принять задачу · required

## Вход
Номер задачи в трекере от человека (`/volna:task 21571`) либо номер в тексте запроса.

## Что делать
1. **Проверить, что предыдущая задача закрыта.** Есть `.volna/state.json` с другой активной
   задачей → сказать об этом и спросить: закрыть её (`/volna:close`) или взять новую поверх.
   Молча переключаться нельзя — журналы и ветки перемешаются.
2. **Гейт чистого дерева.** `git status` в каждом затронутом репозитории. Есть незакоммиченные
   изменения → остановиться и спросить человека, что с ними делать. Worktree в «Волне» нет,
   поэтому это единственная защита от смешивания задач.
3. **Прочитать задачу в трекере**: заголовок, тип (Bug / User Story / Task), описание, вложения,
   обсуждение, связи. Тип определяет ветвление флоу (см. `SKILL.md`). Быстрый способ —
   `node <плагин>/bin/volna-tfs.mjs get <id>`: отдаёт всё это одним компактным markdown
   (чтение, подтверждения не требует). Вложения качать PAT'ом: анонимно трекер отдаёт 401.
4. **Определить репозитории.** По типу задачи и области: UI-багфиксы обычно во `front`,
   порт-задачи — в `back` (пути — в `.volna/project.md`). Не угадывать: проверить по
   постановке и, если неясно, спросить.
5. **Создать ветку** по конвенции из `.volna/project.md`: `bugfix/<id>-<slug>` для bug,
   `feature/<id>-<slug>` для story/task. Ветка создаётся от актуального состояния
   целевой ветки (уточнить у человека, если не очевидно).
6. **Создать журнал** `.volna/journal/TASK-<id>.md` из шаблона скилла `volna-journal` и
   `.volna/state.json` с указателем на него.
7. **Завести чек-лист этапов** в трекере задач сессии — по типу задачи, без лишних этапов
   (для story не заводить implement/tests, если порта не предполагается).
8. Нет `.volna/project.md` → предложить создать из `templates/project.template.md` и заполнить.

## DoD
Ветка создана, дерево чистое, журнал с заполненным frontmatter существует, тип задачи и
список репозиториев зафиксированы, чек-лист этапов виден человеку.

## В журнал
Секция `intake`: что за задача, зачем (проблема пользователя одной строкой), как получена
постановка, ветка, репозитории. Открытые вопросы — сразу в `open[]`.

## Типичные ошибки
- Начать работу, не проверив чистоту дерева, — потом невозможно разделить коммиты.
- Взять номер бага за номер задачи-фикса: задача-фикс появится только на `push-pr`.
- Создать ветку в `back`, когда правка нужна во `front`.
