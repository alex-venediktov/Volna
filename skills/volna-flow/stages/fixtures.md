# Этап 7 · fixtures — оффлайн-снимок данных · optional

Нужен, когда тестам требуется реальный заказ, а его ещё нет в фикстурах.

## Правило
Тесты читают данные из **оффлайн-снимка JSON**, а не из живой БД. Живой доступ делает
тесты хрупкими и недетерминированными.

## Что делать
1. Проверить, нет ли уже подходящей фикстуры (KB-поиск `search_samples` — разобранные
   образцовые данные; затем `Glob` по каталогу фикстур репозитория).
2. Есть → переиспользовать, этап пропустить.
3. Нет → снять снимок нужного заказа/изделия в JSON рядом с существующими фикстурами, по их
   формату и конвенции имён (`order-<номер>.json`).
4. Зафиксировать в журнале: какой заказ, какое изделие, чем снят, что в снимке существенно
   для теста.

## Важно про объём
Снятие фикстуры — **отдельная работа**, а не часть теста. Если снятие оказывается заметным
объёмом (нужна отладка дампера, доступ к БД, чистка данных), это отдельная задача: сказать об
этом человеку, а не растворять её в текущей.

## DoD
Фикстура лежит в репозитории, читается тестом офлайн, в журнале записано её происхождение.

## Типичные ошибки
- Тест, открывающий соединение к живой БД «только на этот раз».
- Снимок с посторонними данными на 20 МБ вместо минимального набора.
- Новая фикстура при наличии подходящей существующей.
