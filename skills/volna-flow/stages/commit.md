# Этап 10 · commit · required

Первое необратимое действие. Выполняется **только по явному «да»** от человека.

## Перед коммитом
1. Пройден `advocate` (или человек сознательно его пропустил).
2. Тесты прогнаны, вывод в журнале.
3. Журнал дописан: последняя итерация `implement` и результат проверок.
4. `git status` просмотрен: понятно, что именно уходит в коммит.

## Как коммитить
1. **`git add -A`** — все изменения, включая **новые (untracked)** файлы. Новые тесты и классы
   обязаны попасть в коммит, иначе они не дойдут до PR. Наблюдался «успешный» коммит без новых
   файлов — проверять обязательно.
2. Сообщение — **одна строка**: `<id-воркайтема> <что сделано>`.
   - для bug до создания задачи-фикса используется номер бага; если задача-фикс уже создана —
     её номер;
   - запрещены: слово «golden», многострочные тела, **любые трейлеры, включая
     `Co-Authored-By`** (это правило проекта; оно переопределяет общие настройки).
3. После коммита проверить: `git status` — дерево чистое, untracked не осталось; `git log -1` —
   HEAD продвинулся, коммит непустой.

## Изменений кода нет
Пустой или фиктивный коммит не делается. Вместо этого — явно сказать «изменений кода нет» и
идти на `close` (ветка «закрыть без PR»).

## Пример
```
git add -A
git commit -m "21571 порт условия видимости клапана при зеркале"
```

## DoD
Коммит существует, содержит все изменения, сообщение по конвенции, дерево чистое, факт
зафиксирован в журнале (хеш и сообщение).

## Типичные ошибки
- `git commit -am` — новые файлы не попадут.
- Многострочное сообщение или трейлер.
- Коммит без разрешения человека.
