# Этап 9 · visual — визуальная сверка · optional

Нужен для всего, что влияет на отрисовку производственного чертежа. Проверяет **человек** —
это единственный этап, где решение принимается глазами.

## Что делать
1. Использовать скилл **`visual-compare`**: рендер бэкенд-примитивов в PNG, side-by-side с
   Delphi-эталоном из `Demo/проверка/*.png`, пиксельная классификация по цвету-смыслу
   (контур / ОС / ЦМ / размеры).
2. Показать человеку результат сверки и **спросить прямо**: где расхождения, что считать
   дефектом. Не решать за него «выглядит похоже».
3. Расхождение подтверждено → `/volna:back implement`, причём **формула выводится из Delphi**,
   а не подгоняется под картинку. PNG — инструмент проверки, не источник истины.
4. Сохранить скриншот: он пригодится на `push-pr` (в PR) и на `close` (в обсуждение бага).
   Для багфикса особенно полезна пара «до / после».

## Когда пропускать
Правка не влияет на отрисовку (расчёт без визуального выхода, инфраструктура, тесты) — этап
пропускается с одной строкой причины в журнале.

## DoD
Человек посмотрел сверку и дал вердикт; вердикт и путь к скриншотам записаны в журнал.

## Типичные ошибки
- Признать совпадение самому, не показав человеку.
- Подогнать код под картинку (прямое нарушение правила порта).
- Не сохранить скриншот — на закрытии задачи прикладывать нечего.
