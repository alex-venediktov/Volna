# Настройки проекта для «Волны»

> Копия этого файла живёт как `.volna/project.md` в рабочем репозитории и **коммитится** —
> это общая для команды часть настроек: команды и конвенции, без секретов и без машинных путей.
>
> Всё приватное — адреса, пути, PAT — берётся из `.env` рабочего репозитория и здесь
> упоминается только именем переменной. Заполнить `.env` по `.env.example` («Волна»),
> проверить — `/volna:doctor`.

## Репозитории

| Имя | Переменная | Что там |
|---|---|---|
| `back` | `REPO_BACK` | бэкенд, основная цель порта |
| `front` | `REPO_FRONT` | UI (опционально) |
| `agent` | `REPO_AGENT` | третий репозиторий (опционально) |

Незаполненная переменная = репозиторий в работе не участвует.

## Эталон

- корень исходников эталона — `DELPHI_REF_ROOT`;
- ключевой модуль, куда смотреть первым — `DELPHI_REF_MAIN`;
- каталог эталонных скриншотов для этапа `visual` — `<заполнить>`;
- **версия эталона критична**: сверяться только с той, что указана командой. Открытая по
  ошибке другая версия — типовая причина «значения не сходятся».

## Трекер задач

- база — `TFS_BASE_URL`, проект — `TFS_PROJECT`, область команды — `TFS_AREA_PATH`;
- доступ — PAT из файла `TFS_PAT_FILE` (utf-8-sig, края обрезаются). Секрет в переменную
  окружения не кладём;
- подвохи REST API (кодировка тела, `$expand=relations`, HTML в многострочных полях) —
  `docs/reference/tfs-rest.md` «Волны»; готовый клиент — `lib/tfs-client.mjs`.

## База знаний

MCP-сервер поиска по коду, эталону, wiki и обсуждениям: имя — `KB_MCP_NAME`, инструменты
`search_delphi`, `search_code`, `search_wiki`, `search_tasks`, `search_samples`.
Сервер не настроен или недоступен → искать `Grep`/`Glob` и отмечать это в журнале.

## Конвенции

- ветка: `bugfix/<id>-<slug>` для bug, `feature/<id>-<slug>` для story/task;
- коммит: одна строка `<id> <что сделано>`; `git add -A` перед коммитом; **без** трейлеров
  (в том числе без `Co-Authored-By`);
- комментарии: одна строка «что делает (`<модуль>.pas:NNNN`)», русский язык,
  ASCII-пунктуация (`->`, `-`, `"`), без номеров задач;
- тесты: PascalCase `Method_State_Expected`, обязательный `/// <summary>`;
- фикстуры: оффлайн-снимок данных в JSON, без обращения к живой БД.

Если в репозитории есть свои скиллы под эти конвенции (стиль комментариев, сообщение коммита,
стиль тестов, порт эталона) — этапы «Волны» используют их; карта соответствия —
`docs/PROJECT-SKILLS.md`.

## Локальное (не коммитить)

Машинно-зависимое — в `.env`; всё, что нужно вынести из этого файла персонально, —
в `.volna/project.local.md` (уже в `.gitignore`).
