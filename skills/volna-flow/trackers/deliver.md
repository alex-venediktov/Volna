# Трекер · deliver — запись о доставке

Открывается на `deliver` при заполненной строке профиля `трекер`. Профиль `трекер: нет` или
`mode: local` — записи в трекер нет, файл не нужен.

Путь до CLI:

```
ls -d ~/.claude/plugins/cache/volna/volna/*/bin/volna-tracker.mjs | sort -V | tail -1
```

## Задача-фикс и PR

Заводит ли трекер задачу-фикс и PR, говорит `capabilities` (`fix-task`, `pr`) и таблица ниже. Не
заводит — шага нет: работа ведётся в самой задаче, её id стоит в ветке и в префиксе коммита,
`fix_task` в журнале остаётся пустым, PR человек создаёт сам, и причина в журнал не пишется. Связь
«задача — изменения» тогда держится id в сообщении коммита и записью ниже.

## Что записать в задачу

Где трекер заводит задачу-фикс, запись о доставке — сама задача-фикс и PR, комментарий не нужен;
правила записи ниже действуют и для неё.

```
node <плагин>/bin/volna-tracker.mjs comment <id> --body-file <файл>
node <плагин>/bin/volna-tracker.mjs describe <id> --body-file <файл> [--replace]
```

- одна короткая запись о том, что доставлено и чем проверено: хеш коммита, ветка, суть правки;
- вход — **Markdown**: разметку трекера собирает обёртка, вход она экранирует, поэтому поданные
  руками теги или wiki-разметка видны в трекере текстом;
- длинный текст — `--body-file`, а не аргументом: кириллица в командной строке бьётся, а файл
  читается как UTF-8;
- `describe` по умолчанию **дописывает** абзац, `--replace` заменяет описание целиком — текст
  постановщика не затирать;
- флага подтверждения у команд нет: решение о необратимом принимает человек в разговоре, а
  `--dry-run` печатает, что уйдёт в трекер, ничего не отправляя. Одно изменение — одно
  подтверждение.

## Специфика трекера

| Трекер | Файл | Что там |
|---|---|---|
| `tfs` | `trackers/tfs/deliver.md` | задача-фикс, поля процесса, PR и связи |
| `jira` | нет | задача-фикс и PR не заводятся |
| `task-tracker` | нет | задача-фикс и PR не заводятся |
