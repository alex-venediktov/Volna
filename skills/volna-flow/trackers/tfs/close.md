# TFS · close — статусы, часы, остаток

Открывается на `close` при профиле `трекер: tfs` в ветвях А-В. Ветвь Г (`mode: local`,
`трекер: нет`, `закрытие: журнал`) файл не открывает: в трекер не уходит ничего.

Путь до CLI:

```
ls -d ~/.claude/plugins/cache/volna/volna/*/bin/volna-tfs.mjs | sort -V | tail -1
```

(или готовая команда из `.volna/project.md`).

## Команды

```
node <плагин>/bin/volna-tfs.mjs state <id> Resolved --assign "<тестер>"
node <плагин>/bin/volna-tfs.mjs time <id> <часы>
node <плагин>/bin/volna-tfs.mjs estimate <id> --remaining 0
node <плагин>/bin/volna-tfs.mjs describe <id> --body-file <файл>
node <плагин>/bin/volna-tfs.mjs attach <id> <артефакт> --discussion --comment "<одна строка>"
node <плагин>/bin/volna-tfs.mjs link-pr <id> <url PR>
node <плагин>/bin/volna-tfs.mjs states <тип>          допустимые состояния и причины
node <плагин>/bin/volna-tfs.mjs pr status <репо> <номер>   слито ли, что встанет само
```

- `time` **прибавляет** к уже списанному; `--set` заменяет;
- `estimate --remaining 0` обнуляет остаток; `--original` не трогать — она показывает, во что
  задачу оценивали;
- флага подтверждения у команд нет — решение принимает человек в разговоре: **одно изменение —
  одно подтверждение**, пакетом не гнать. Показать, что уйдёт в трекер, не отправляя, — тот же
  вызов с `--dry-run`.

## Правила записи

- многострочный текст — **Markdown** (абзацы, списки `-` и `1.`, заголовки `#`, код, ссылки):
  HTML собирает обёртка, вход она экранирует, поэтому поданные теги видны в трекере текстом.
  Однострочные поля (эстимация, заголовок, назначение) — простым текстом;
- PAT — из файла (utf-8-sig, обрезать края), тело запроса — UTF-8 байтами. Это типовая причина
  ошибок TF401319/TF401320;
- **абзац об ограничении — командой `describe`** (по умолчанию дописывает, `--replace` заменяет
  целиком): текст постановщика не затирается. Длинный текст передавать `--body-file`;
- **причину смены состояния свободным текстом сервер не примет** — только значение из списка
  процесса, иначе откатывается весь запрос вместе со сменой состояния. Список — `states <тип>`;
  подходящего значения нет → менять состояние без `--reason`, а причину писать текстом в задачу;
- закрытая задача полей может не отдать: правило перехода процесса запрещает трогать часы и
  остаток после закрытия. Отсюда порядок — часы и остаток **до** статуса закрытия, а в режиме
  «слияние PR» — до слияния.
