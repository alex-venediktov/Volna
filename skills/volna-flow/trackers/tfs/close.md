# TFS · close — особенности

Открывается после `trackers/close.md` при профиле `трекер: tfs`.

## Команды сверх общих

```
node <плагин>/bin/volna-tracker.mjs state <id> на-проверке --assign "<тестер>"
node <плагин>/bin/volna-tracker.mjs attach <id> <артефакт> --discussion --comment "<одна строка>"
node <плагин>/bin/volna-tracker.mjs link-pr <id> <url PR>
node <плагин>/bin/volna-tracker.mjs states <тип>               допустимые состояния и причины
node <плагин>/bin/volna-tracker.mjs pr status <репо> <номер>   слито ли, что встанет само
```

- `на-проверке` (`Resolved`) с `--assign` — маршрут тестеру в режиме `закрывающий вручную`;
- `time --set` заменяет списанное, а не прибавляет;
- `describe --replace` заменяет описание целиком.

## Правила записи

- PAT — из файла (utf-8-sig, обрезать края), тело запроса — UTF-8 байтами. Это типовая причина
  ошибок TF401319/TF401320;
- **причину смены состояния свободным текстом сервер не примет** — только значение из списка
  процесса, иначе откатывается весь запрос вместе со сменой состояния. Список — `states <тип>`;
  подходящего значения нет → менять состояние без `--reason`, а причину писать текстом в задачу.
