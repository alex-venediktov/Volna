# TFS · split — ребёнок дочерним элементом

Открывается на `/volna:split`, когда человек выбрал детей в трекере. Родитель — задача трекера
(`mode: tracker`); у локального родителя в трекере нет элемента, и дети остаются локальными.

Путь до CLI:

```
ls -d ~/.claude/plugins/cache/volna/volna/*/bin/volna-tfs.mjs | sort -V | tail -1
```

## Команды, по паре на ребёнка

```
node <плагин>/bin/volna-tfs.mjs create Task --title "<заголовок>" --parent <id родителя> \
     --estimate <часы> [--body-file <постановка>] [--like <id соседней задачи>]
node "${CLAUDE_PLUGIN_ROOT}/bin/volna-task.mjs" add <родитель> --tracker <id из ответа> \
     [--url "<ссылка>"] --title "<заголовок>" --goal "<постановка>"
```

`--url` — ссылка того же вида, что в `tracker:` родителя, с id ребёнка; у родителя её нет —
флаг не нужен.

- **сначала элемент, потом журнал**: `add` сети не имеет и принимает id готового элемента. Элемент
  создан, а `add` отказал — повторить только `add`, второй элемент не заводить;
- ребёнок бага — дочерний `Task`, то есть уже задача-фикс: на его `deliver` второй задачи-фикса не
  создаётся, `fix_task` пуст, номер в PR — его собственный;
- исполнитель, обязательные поля и оценка — как у задачи-фикса (`deliver.md`, «Задача-фикс»):
  ответ команды сверить сразу;
- одно заведение — одно подтверждение не нужно: состав детей человек уже принял одним «да».
