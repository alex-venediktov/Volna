# TFS · deliver — задача-фикс, связи, PR

Открывается после `trackers/deliver.md` при профиле `трекер: tfs`.

## Задача-фикс: что в ней должно быть

Создаётся для bug **до push**, чтобы в PR стоял её номер, а не номер бага.

- описание **краткое**: суть правки в 1-2 предложениях, без простыней, Markdown файлом;
- эстимация и привязка к багу (родитель или related);
- **исполнитель** — текущий пользователь по умолчанию, другой ставится `--assign` осознанно.
  Ответ команды печатает исполнителя и состояние: сверить их **сразу**. Потом не выйдет — в поле
  уже будет стоять исправленное человеком значение, и оно выглядит как исходное;
- обязательные поля процесса — `fields <тип>` до создания, значение с соседней задачи области —
  `--like <id>`;
- рекламация → сослаться на прежнюю задачу-фикс и её PR;
- id задачи-фикса → в `fix_task` frontmatter журнала.

## Команды

```
volna-tracker create Task --title "<суть>" --parent <id бага> --estimate <часы> \
                    [--tags A,B] [--body-file <файл>] [--field <ref>=<значение>] \
                    [--like <id соседней задачи>] [--assign <кто>]               задача-фикс
volna-tracker fields <тип>                      обязательные поля процесса и их значения
volna-tracker whoami                            кто будет исполнителем по умолчанию
volna-tracker pr list <репо> --source <ветка>   не создан ли PR на эту ветку раньше
volna-tracker pr create <репо> <ветка> --title "<номер>: суть" --body-file <файл> \
                    [--target <ветка>] [--work-item <номер>]
volna-tracker pr status <репо> <номер>          состояние: слияние, коммиты
volna-tracker link-pr <id> <репо> <номер>       связь задача-PR, если PR уже создан
volna-tracker link <id> <цель> [--rel related|duplicate]   связь между задачами
```

- `create` без `--estimate` заводит задачу без часов и об этом предупреждает: по конвенции
  команды оценка и остаток у новой задачи равны и заполняются сразу;
- процесс трекера может требовать полей, которых нет среди флагов (контроль проекта, приоритет):
  посмотреть их заранее — `fields <тип>`, снять значение с соседней задачи области — `--like <id>`.
  На отказе `TF401320` команда сама печатает поле, допустимые значения процесса и то, что стоит в
  этом поле у родителя, но не подставляет молча. Значение постоянно для области — его место
  **знание** (`.volna/wiki/process/tfs/`, указатель этапа `deliver`), а не переменная окружения.
  Собирать запрос вручную в обход CLI не надо;
- `--work-item` ставит нативную связь сразу — без неё трассировка задача-PR теряется;
- целевая ветка: `--target` или `TARGET_BRANCH` в `.env`. Угадывать её команда не будет;
- после создания посмотреть `mergeStatus`: `conflicts` — PR слить нельзя, говорить «готово» рано;
- **несколько коммитов в PR** = ветка отведена не от целевой, а от другой feature-ветки. Тогда
  порядок слияния важен, и его надо назвать человеку явно.

## Типичные ошибки

- **HTML руками** в описание work item → теги видны в тексте постановки. Исправляется повторной
  записью `describe --replace`.
- Задача-фикс без исполнителя или на чужом человеке: проверять по печати команды, а не по полю
  в трекере после ручной правки.
- Push до создания задачи-фикса → в PR номер бага, трассировка теряется.
