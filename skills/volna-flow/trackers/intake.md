# Трекер · intake — прочитать задачу

Открывается на `intake` при заполненной строке профиля `трекер` (`tfs`, `jira`, `task-tracker`).
Профиль `трекер: нет` или `mode: local` — файл не нужен: читать нечего.

Работа с трекером идёт через общий CLI плагина `volna-tracker`, а не сырым REST и не инструментами
MCP модели: шлюз своего трекера он выбирает по строке профиля сам. Путь:

```
ls -d ~/.claude/plugins/cache/volna/volna/*/bin/volna-tracker.mjs | sort -V | tail -1
```

## Прочитать задачу

```
node <плагин>/bin/volna-tracker.mjs get <id>
```

Отдаёт заголовок, тип, статус, постановку, связи и обсуждение одним компактным markdown. Команда
читающая, подтверждения не требует. Идентификатор — как в трекере, регистр и префикс не меняются:
он идёт в имя журнала, в ветку и в префикс коммита.

## Свои задачи

```
node <плагин>/bin/volna-tracker.mjs query [<выборка>]
```

Выборка — на языке трекера: TFS — WIQL (можно только условие после `WHERE`), Jira — JQL (без
него — `JIRA_JQL_MINE`), task-tracker — статус (без него — свой проект, кроме `done`). Ответ бывает
обрезан пределом страниц — команда это говорит, тогда выборку уточнить, а не поднимать предел.

## Что взять из ответа

Тип задачи определяет ветвление флоу; для бага — ещё и родителя: постановка чаще там, а не в
самом баге, и читается тем же `get`.

## Специфика трекера

После этого файла — файл своего трекера, если он есть:

| Трекер | Файл | Что там |
|---|---|---|
| `tfs` | `trackers/tfs/intake.md` | вложения за авторизацией |
| `jira` | `trackers/jira/intake.md` | вид для флоу, родитель в чужом проекте, вложения |
| `task-tracker` | `trackers/task-tracker/intake.md` | форма id, вид по префиксу, родитель строкой, сервер недоступен |
