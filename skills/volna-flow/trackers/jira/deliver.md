# Jira · deliver — запись о доставке в задачу

Открывается на `deliver` при профиле `трекер: jira`. Профиль `трекер: нет` или `mode: local` —
записи в трекер нет, файл не нужен.

Путь до CLI:

```
ls -d ~/.claude/plugins/cache/volna/volna/*/bin/volna-jira.mjs | sort -V | tail -1
```

## Чем этот этап отличается от того же этапа на TFS

- **задача-фикс не создаётся.** Работа ведётся в самой задаче, её ключ стоит в ветке и в префиксе
  коммита. Создание задач через CLI пока не поддержано, `fix_task` в журнале остаётся пустым;
- **pull request не заводится.** Репозиторий проекта живёт вне Jira (Bitbucket), профиль доставки
  остаётся `commit+push`, PR человек создаёт сам. Связь «задача — изменения» держится ключом в
  сообщении коммита.

## Что записать в задачу

```
node <плагин>/bin/volna-jira.mjs comment <ключ> --body-file <файл>
node <плагин>/bin/volna-jira.mjs describe <ключ> --body-file <файл> [--replace]
```

- одна короткая запись о том, что доставлено и чем проверено: ветка, суть правки, способ проверки;
- вход — **markdown**: wiki-разметку Jira собирает обёртка, вручную её писать не надо. Длинный
  текст передавать `--body-file`, а не аргументом: кириллица в командной строке бьётся;
- `describe` по умолчанию **дописывает** абзац, `--replace` заменяет описание целиком — текст
  постановщика затирать не надо;
- флага подтверждения у команд нет: решение о необратимом принимает человек в разговоре, а
  `--dry-run` печатает намерение, ничего не отправляя. Одно изменение — одно подтверждение.
