# Jira · close — статус, часы, остаток

Открывается на `close` при профиле `трекер: jira` в ветвях А-В. Ветвь Г (`mode: local`,
`трекер: нет`, `закрытие: журнал`) файл не открывает: в трекер не уходит ничего.

Путь до CLI:

```
ls -d ~/.claude/plugins/cache/volna/volna/*/bin/volna-jira.mjs | sort -V | tail -1
```

## Команды

```
node <плагин>/bin/volna-jira.mjs time <ключ> <часы> [--comment "<что делали>"]
node <плагин>/bin/volna-jira.mjs estimate <ключ> --remaining 0
node <плагин>/bin/volna-jira.mjs state <ключ> "<статус или переход>"
node <плагин>/bin/volna-jira.mjs states <ключ>          что доступно из текущего статуса
node <плагин>/bin/volna-jira.mjs comment <ключ> --body-file <файл>
```

## Порядок и правила

- **часы и остаток — до смены статуса**: правило перехода может запретить трогать время после
  закрытия, и тогда списание уже не пройдёт;
- `time` **прибавляет** к затраченному и на столько же уменьшает остаток. Часы задаются числом
  (`1.5`), обёртка переводит их в запись Jira (`1h 30m`). Единица дня в проекте настраивается
  (по умолчанию 8 часов), поэтому часы надёжнее дней;
- `estimate --remaining 0` обнуляет остаток; `--original` не трогать — она показывает, во что
  задачу оценивали;
- **статус меняется переходом рабочего процесса**: команда принимает и имя перехода, и имя
  целевого статуса, а недоступный переход печатает списком доступных и ничего не меняет. Имена
  статусов в проекте бывают на разных языках (`В работе`, `For testing`, `Ready to prod`) —
  брать их из `states <ключ>`, а не из головы;
- флага подтверждения у команд нет: решение принимает человек в разговоре, **одно изменение —
  одно подтверждение**, пакетом не гнать. Показать, что уйдёт в трекер, не отправляя, — тот же
  вызов с `--dry-run`;
- итог работы пишется **комментарием** (`comment`), а не в описание: описание принадлежит
  постановщику.
