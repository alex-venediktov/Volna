# Jira · intake — прочитать задачу

Открывается на `intake` при профиле `трекер: jira`. Профиль `трекер: нет` или `mode: local` —
файл не нужен: читать нечего.

Идентификатор задачи здесь — **строковый ключ** вида `ABC-2228`, а не число. Он же идёт в имя
журнала (`TASK-ABC-2228.md`), в имя ветки и в префикс коммита.

Работа с трекером идёт через CLI плагина, а не сырым REST. Путь:

```
ls -d ~/.claude/plugins/cache/volna/volna/*/bin/volna-jira.mjs | sort -V | tail -1
```

(или готовая команда из `.volna/project.md`).

## Прочитать задачу

```
node <плагин>/bin/volna-jira.mjs get <ключ>
```

Отдаёт заголовок, тип, статус, исполнителя, родителя, метки, время, связи, вложения, постановку
и обсуждение одним компактным markdown. Команда читающая, подтверждения не требует.

## Что взять из ответа

- **вид задачи для флоу** команда называет сама (`тип: Баг (вид для флоу: bug)`). Опираться надо
  на него, а не на имя типа: одно и то же поле приходит то переведённым (`Задача`, `Баг`,
  `История`), то исходным (`Task`, `Bug`, `Story`) — язык ответа зависит от учётной записи и от
  эндпоинта;
- **родитель бывает в чужом проекте** (`ABC-2228` → родитель `XYZ-4475`): постановка часто
  там, и `get` по ключу родителя работает так же, хотя `JIRA_PROJECT` указывает на другой проект;
- вложения перечислены именами; скачивание в этот заход не входит — файл открывается в браузере.

## Свои задачи

```
node <плагин>/bin/volna-jira.mjs query                 выборка из JIRA_JQL_MINE
node <плагин>/bin/volna-jira.mjs query "<jql>"         произвольный JQL
```

Ответ страничный и обрезается пределом страниц; команда сама говорит, что обрезала, — тогда
запрос надо уточнить, а не поднимать предел вслепую.
