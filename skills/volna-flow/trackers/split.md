# Трекер · split — ребёнок элементом трекера

Открывается на `/volna:split`, когда человек выбрал детей в трекере. Родитель — задача трекера
(`mode: tracker`); у локального родителя в трекере нет элемента, и дети остаются локальными.

Путь до CLI:

```
ls -d ~/.claude/plugins/cache/volna/volna/*/bin/volna-tracker.mjs | sort -V | tail -1
```

## Команды, по паре на ребёнка

```
node <плагин>/bin/volna-tracker.mjs create <тип> --title "<заголовок>" --parent <id родителя> \
     [--estimate <часы>] [--body-file <постановка>]
node "${CLAUDE_PLUGIN_ROOT}/bin/volna-task.mjs" add <родитель> --tracker <id из ответа> \
     [--url "<ссылка>"] --title "<заголовок>" --goal "<постановка>"
```

`--url` — ссылка того же вида, что в `tracker:` родителя, с id ребёнка; у родителя её нет —
флаг не нужен.

- **сначала элемент, потом журнал**: `add` сети не имеет и принимает id готового элемента. Элемент
  создан, а `add` отказал — повторить только `add`, второй элемент не заводить;
- `--estimate` — там, где шлюз умеет оценку (`capabilities`: `estimate`); не умеет — флаг не
  передавать;
- ответ команды (id, исполнитель, родитель) сверить сразу;
- одно заведение — одно подтверждение не нужно: состав детей человек уже принял одним «да».

## Специфика трекера

| Трекер | Файл | Что там |
|---|---|---|
| `tfs` | `trackers/tfs/split.md` | тип `Task`, ребёнок бага — уже задача-фикс, поля процесса |
| `jira` | `trackers/jira/split.md` | тип ребёнка от родителя, проект по ключу |
| `task-tracker` | `trackers/task-tracker/split.md` | вид вместо типа, связь строкой, отмена через `done` |
