# Трекер · close — часы, остаток, статус, итог

Открывается на `close` при заполненной строке профиля `трекер` в ветвях А-В. Ветвь Г
(`mode: local`, `трекер: нет`, `закрытие: журнал`) файл не открывает: в трекер не уходит ничего.

Путь до CLI:

```
ls -d ~/.claude/plugins/cache/volna/volna/*/bin/volna-tracker.mjs | sort -V | tail -1
```

## Команды

```
node <плагин>/bin/volna-tracker.mjs time <id> <часы>
node <плагин>/bin/volna-tracker.mjs estimate <id> --remaining 0
node <плагин>/bin/volna-tracker.mjs comment <id> --body-file <файл>
node <плагин>/bin/volna-tracker.mjs describe <id> --body-file <файл>
node <плагин>/bin/volna-tracker.mjs state <id> закрыта | на-проверке
node <плагин>/bin/volna-tracker.mjs states [<тип|ключ>]  что доступно: TFS - тип, Jira - ключ или тип
```

## Порядок и правила

- **часы и остаток — до смены статуса**: правило перехода может запретить трогать поля после
  закрытия, и тогда списание уже не пройдёт; в режиме «слияние PR» — до слияния;
- `time` **прибавляет** к уже списанному; `estimate --remaining 0` обнуляет остаток, `--original`
  не трогать — она показывает, во что задачу оценивали;
- **шлюз не умеет часы или оценку** (`capabilities` без `time`, `estimate`) — команда отвечает
  кодом 4 «шлюз не умеет», шаг не делается: часы и итог идут в журнал, как в ветви Г;
- статус — по смыслу: `закрыта`, либо `на-проверке`, если по процессу задачу дальше ведёт тестер.
  Имя в трекере — из «## Статусы трекера» `.volna/project.md`, без строки — умолчание шлюза;
- итог работы — **комментарием** (`comment`), до смены статуса; абзац об ограничении — `describe`,
  он дописывает к описанию, а не затирает текст постановщика;
- многострочный текст — **Markdown** файлом (`--body-file`): разметку трекера собирает обёртка,
  поданные руками теги видны в трекере текстом. Однострочные поля — простым текстом;
- флага подтверждения у команд нет — решение принимает человек в разговоре: **одно изменение —
  одно подтверждение**, пакетом не гнать. Показать, что уйдёт в трекер, не отправляя, — тот же
  вызов с `--dry-run`.

## Специфика трекера

| Трекер | Файл | Что там |
|---|---|---|
| `tfs` | `trackers/tfs/close.md` | маршрут тестеру, вложение в обсуждение, связь с PR, причина смены состояния, PAT |
| `jira` | `trackers/jira/close.md` | часы в записи Jira, переходы рабочего процесса |
| `task-tracker` | `trackers/task-tracker/close.md` | `review` не ставится, удаления нет |
