# task-tracker · deliver — запись о доставке в задачу

Открывается на `deliver` при профиле `трекер: task-tracker`. Профиль `трекер: нет` или
`mode: local` — записи в трекер нет, файл не нужен.

Путь до CLI:

```
ls -d ~/.claude/plugins/cache/volna/volna/*/bin/volna-tracker.mjs | sort -V | tail -1
```

## Чем этот этап отличается от того же этапа на TFS

- **задача-фикс не создаётся**: работа ведётся в самой задаче, её id стоит в ветке и в префиксе
  коммита, `fix_task` в журнале остаётся пустым;
- **pull request не заводится**: репозиторий живёт вне трекера, PR человек создаёт сам. Связь
  «задача — изменения» держится id в сообщении коммита и комментарием с хешем.

## Что записать в задачу

```
node <плагин>/bin/volna-tracker.mjs comment <id> --body-file <файл>
node <плагин>/bin/volna-tracker.mjs describe <id> --body-file <файл> [--replace]
```

- одна короткая запись о том, что доставлено и чем проверено: хеш коммита, ветка, суть правки;
- вход — markdown как есть; длинный текст — `--body-file`: кириллица в командной строке бьётся;
- `describe` по умолчанию **дописывает** абзац к постановке (сервер принимает поле только целиком,
  CLI читает прежнюю и склеивает), `--replace` заменяет постановку — текст постановщика не затирать;
- флага подтверждения нет: решение о необратимом — в разговоре, `--dry-run` печатает намерение.
