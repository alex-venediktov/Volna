# task-tracker · intake — прочитать задачу

Открывается на `intake` при профиле `трекер: task-tracker`. Профиль `трекер: нет` или `mode: local` —
файл не нужен: читать нечего.

Идентификатор задачи — **как на сервере**: короткий номер (`1`) у задач, заведённых не «Волной»,
либо `<префикс>-<N>` (`feature-3`, `bugfix-8`, `research-5`) у заведённых ею. Он идёт в имя журнала
(`TASK-feature-3.md`), в префикс коммита и в ветку `<префикс>/<N>_<slug>` (у голого номера
префикс — по виду задачи).

Работа с трекером идёт через общий CLI плагина, а не инструментами MCP модели. Путь:

```
ls -d ~/.claude/plugins/cache/volna/volna/*/bin/volna-tracker.mjs | sort -V | tail -1
```

## Прочитать задачу

```
node <плагин>/bin/volna-tracker.mjs get <id>
```

Отдаёт проект, статус, теги, **вид для флоу**, ссылку на страницу и постановку markdown вместе с
секцией «Обсуждение». Команда читающая, подтверждения не требует.

## Что взять из ответа

- **вид для флоу** команда называет сама: префикс id (`bugfix` — bug, `feature` — task, `research` —
  research), без префикса — тег `bug` или `research`, иначе task. Типа задачи у сервера нет;
- **родителя у сервера нет**: ребёнок, заведённый «Волной», несёт строку `родитель: <id>` первой
  строкой постановки — постановку родителя читать тем же `get`;
- **сервер недоступен** (адрес в сети без хоста не отвечает за `TT_TIMEOUT_MS`) — останов с причиной,
  а не тихий переход в локальный режим: человеку — вести задачу локально текстом или вернуться к ней
  из сети.

## Свои задачи

```
node <плагин>/bin/volna-tracker.mjs query                 свой проект (TT_PROJECT), кроме done
node <плагин>/bin/volna-tracker.mjs query <статус>        только этот статус
```
