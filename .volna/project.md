# Настройки проекта для «Волны»

> Репозиторий самой «Волны», который ведут по «Волне». Файл коммитится: это командная часть
> настроек. Приватное — в `.env`, здесь только имена переменных.
> Проверить — `/volna:doctor`.

## Профиль

- репозитории: один
- трекер: нет
- приём задач: текст
- доставка: commit+push
- закрытие: журнал
- эталон: нет

Плагин разрабатывается в одном репозитории, задачи ставятся своими словами (трекера у него нет),
результат уезжает коммитом в `main` — pull request на своём же репозитории не заводим.
Сверять правки не с чем: эталонной реализации у процессного плагина не бывает.

## Репозитории

Профиль `репозитории: один`: правки идут в этот репозиторий, `repos[]` в журнале остаётся пустым.

## Команды

| Зачем | Команда |
|---|---|
| тесты hooks | `node hooks/test-hooks.mjs .` |
| тесты CLI над трекером | `node bin/test-volna-tfs.mjs` |
| замер стоимости компонентов | `claude plugin details volna@volna` |

Сборки нет: плагин — это markdown и Node без зависимостей.

## Конвенции

- ветка: работа идёт прямо в `main`, ветка заводится только под крупную правку в несколько
  заходов; целевая ветка — `TARGET_BRANCH`;
- коммит: одна строка `версия плагина <X.Y.Z>: <что сделано>`; `git add -A` перед коммитом;
  **без** трейлеров (в том числе без `Co-Authored-By`);
- версия правится в `.claude-plugin/plugin.json` и `.claude-plugin/marketplace.json` вместе с
  правкой, а не отдельным коммитом; тег ставится на выпуск, и сразу за ним — строка версии
  в `docs/STATUS.md`;
- каждое решение по устройству плагина дописывается в `docs/STATUS.md` нумерованным пунктом:
  что наблюдалось → что сделано → что отвергнуто и почему;
- комментарии: одна строка «что делает (`<источник>`)», русский язык,
  ASCII-пунктуация (`->`, `-`, `"`), без номеров задач;
- тесты: проверка формулируется утверждением о поведении (`check("push при mode: local: гейт
  молчит", ...)`), новый механизм без проверки не выпускается.

## Локальное (не коммитить)

Машинно-зависимое — в `.env`; персональное — в `.volna/project.local.md` (уже в `.gitignore`).
