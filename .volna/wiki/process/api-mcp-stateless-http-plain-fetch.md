# MCP-сервер без сессии зовётся голым `fetch`, а ошибку инструмента выдаёт поле, не HTTP

**тип:** особый случай · **предмет:** клиент MCP по HTTP · **этапы:** analyze, plan, implement
**зона:** api · **раздел:** process

**вывод:** довод «MCP нельзя звать из hooks, `doctor` и тестов» верен для инструментов модели,
но не для сервера Streamable HTTP, который не держит сессию. Признак - `initialize` не отдаёт
заголовок `Mcp-Session-Id`: тогда каждый `tools/call` - отдельный POST JSON-RPC, и CLI на Node
без зависимостей зовёт те же команды сервера сам, с таймаутом и подставным `fetch` в тесте.

Два подвоха клиента: ошибка инструмента приходит с HTTP 200 и `isError: true` (код ответа её не
выдаёт), а адрес в сети без хоста не отказывает, а висит - без `AbortSignal.timeout` клиент ждёт.

**Признак применимости:** запросить `initialize` и посмотреть заголовки ответа. Сессия есть
(заголовок пришёл) или нужен OAuth - этот приём не годится, остаётся путь через инструменты модели.
