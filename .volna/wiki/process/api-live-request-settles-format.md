# Развилку по внешнему API закрывает один живой запрос, а не чтение документации

**тип:** приём · **предмет:** выбор версии внешнего API · **этапы:** analyze, spec
**зона:** api · **раздел:** process

**вывод:** когда от формата ответа зависит устройство клиента, дешевле сходить в живой экземпляр
одним читающим запросом, чем собирать ответ из документации и обсуждений. Документация говорит,
как задумано; экземпляр говорит, что придёт, — вместе с настройками, локализацией и выведенными
из обращения адресами.

Наблюдалось на выборе версии REST для второго трекера. Развилка «строка разметки против дерева
JSON» определяла весь ввод-вывод; два запроса к одной и той же задаче в разных версиях закрыли
её за минуту и заодно дали три факта, которых в постановке не было: прежний адрес поиска
отвечает 410, у нового поиска нет поля `total`, а имя типа задачи приходит переведённым или
исходным в зависимости от эндпоинта.

**Осторожно:** проверять надо на данных, где поле заполнено. Пустое значение приходит как `null`,
и проверка типа в JavaScript тогда врёт (`typeof null === "object"`) — первая же попытка показала
«дерево» там, где описания просто не было.

**Граница:** приём касается чтения. Запись в чужой боевой трекер так не проверяют — на неё нужна
и задача, куда писать разрешено, и разрешение человека.
