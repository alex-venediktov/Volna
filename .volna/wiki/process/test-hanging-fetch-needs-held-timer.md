# Заглушка висящего сервера в тесте Node обязана держать свой таймер, иначе процесс выходит раньше таймаута

**тип:** ограничение · **предмет:** проверка таймаута клиента · **этапы:** unit-tests, implement
**раздел:** process

**вывод:** проверка «сервер не ответил - клиент отказал по таймауту» на подставном `fetch`, который
просто не разрешает обещание, в Node до таймаута не доживает. Таймер `AbortSignal.timeout` процесс
живым не держит (настоящий запрос держит открытый сокет, заглушка - ничего), цикл событий пустеет,
и Node выходит кодом 13 с предупреждением «unsettled top-level await»: ни `OK`, ни `FAIL` по
проверке не печатается, итоговая строка набора тоже.

Заглушка заводит свой обычный `setTimeout` дольше таймаута клиента, снимает его по `abort` сигнала
и отклоняет обещание причиной сигнала; сработал её таймер - значит, таймаут клиента не сработал,
и это тоже отказ с понятным текстом.

**источник:**
- `bin/test-volna-tt.mjs:124` — `таймер держит процесс, как держал бы открытый сокет: таймер сигнала процесс не держит`
- `bin/test-volna-tt.mjs:126` — `const hold = setTimeout(() => reject(new Error("таймаут клиента не сработал")), 2000);`
- `lib/tt-client.mjs:136` — `signal: AbortSignal.timeout(this.timeoutMs),`
