# Массовая правка скриптом на Python переводит файлы в CRLF

**тип:** побочный эффект · **предмет:** правка одинаковой строки в десятках файлов · **этапы:** implement
**раздел:** process

**вывод:** `pathlib.Path.write_text()` на Windows открывает файл в текстовом режиме с
`newline=None`, поэтому каждый `\n` уходит на диск как `\r\n`. Одинаковая правка в двадцати файлах
разом переводит их все в CRLF, а `.gitattributes` с `*.md text eol=lf` начинает печатать
`CRLF will be replaced by LF` на каждый файл в `git status`.

Как делать: писать байтами (`write_bytes`) либо передавать `newline="\n"`. Как починить уже
записанное: байтовая замена `\r\n` на `\n` по списку `git diff --name-only`.

Сам приём (одна и та же строка в десятках файлов - скриптом, а не двадцатью правками руками)
остаётся верным: ошибку даёт способ записи, а не замена.
