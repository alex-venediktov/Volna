# Пустой ответ внешнего API не факт, пока не проверен доступ

**тип:** ограничение · **предмет:** отрицательный ответ на чтение · **этапы:** implement, unit-tests
**зона:** api · **раздел:** process

**вывод:** сервер вправе отвечать на запрос без прав не отказом, а пустотой или «не найдено».
Клиент, который печатает такой ответ как результат, сообщает человеку неправду с уверенным видом.
Отрицательный ответ на чтение обязан перепроверяться отдельным вызовом, который об отказе говорит
честно, — и только после этого подаваться как факт.

Наблюдалось на Jira Cloud: с недействительным токеном `/search/jql` отдаёт
`200 {"issues":[],"isLast":true}`, чтение задачи и проекта — `404` «не существует либо нет прав»,
и лишь `/myself` отвечает 401. Тот же пустой список приходит и на запрос вовсе без авторизации:
запрос обрабатывается как анонимный. Человек читает «найдено: 0» как ответ трекера и работает
дальше, не зная, что доступа нет.

**Признак:** у команды есть «отрицательный» исход, который выглядит нормальным ответом (пусто,
ноль, не найдено). Спросить: отличит ли его человек от отказа в доступе, если смотрит только на
вывод? Не отличит - нужна перепроверка на этом исходе.

**Цена:** проверка зовётся только на отрицательном ответе, то есть редко; на обычном пути лишнего
запроса нет.

**Почему не ловится тестами:** подставной клиент отвечает так, как задумано, а не так, как отвечает
сервер. Этот класс дефектов находит живой прогон.
