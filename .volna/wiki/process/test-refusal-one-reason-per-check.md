# Проверка отказа, у которой есть другая причина отказать, защиту не проверяет

**тип:** ограничение · **предмет:** проверки отказа и защиты пути · **этапы:** unit-tests, advocate
**раздел:** process

**вывод:** проверка «на плохой вход - отказ без записи» зелёная, если отказ случился по **любой**
причине. Когда у входа их две - защита, которую проверяют, и посторонняя (файла нет, активна
чужая задача), - проверка остаётся зелёной и без защиты. Так проверка id с переходом вверх
(`../journal/TASK-x`) отказывает сама собой: после склейки с префиксом `TASK-` первый сегмент -
`TASK-..`, имя каталога, а не переход, и файла по такому пути нет.

Плохой вход подбирается так, чтобы без защиты он **дошёл до цели**: `x/../TASK-<id>` после
нормализации пути указывает на настоящий журнал. Прочие препятствия с пути убираются - например,
пустой `state.json` вместо чужой активной задачи. Годность проверяет мутация: защита выключена -
проверка обязана покраснеть.
