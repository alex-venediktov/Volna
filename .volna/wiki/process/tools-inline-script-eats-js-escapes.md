# Вставка JS-кода через скрипт в shell теряет экранирование: литерал рвётся переводом строки

**тип:** побочный эффект · **предмет:** правка `.mjs` скриптом из heredoc или `node -e` · **этапы:** implement, unit-tests
**раздел:** process

**вывод:** фрагмент JS, который несёт `\n`, `\s` или `\\`, проходит два разбора экранирования -
строки скрипта-вставщика и затем самого JS. В обычной (не raw) строке Python `"\n"` становится
настоящим переводом строки, и в файл уходит `s.split("` + перевод + `")` - модуль не
загружается (`SyntaxError: Invalid or unexpected token`); класс `[\\/]` пришёл в файл как `[\/]`,
без обратного слеша, - код загружается и молча проверяет не то. `node -e '...'` в
одинарных кавычках shell и шаблонная строка JS внутри дают тот же эффект на `\\n`.

Правка кода с обратными слешами идёт инструментом правки (`Edit`) - строка попадает в файл как
написана. Скрипт-вставщик годится для текста без экранирования; нужен всё-таки он - блок кода
кладётся во временный файл heredoc'ом с `'EOF'` и читается скриптом как данные, а не как литерал.
