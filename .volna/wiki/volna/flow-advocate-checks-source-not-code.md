# На задаче без кода адвокат ищет факт, которого нет в источнике

**тип:** приём · **предмет:** адвокат на задаче без кода · **этапы:** advocate, implement
**раздел:** volna

**вывод:** `advocate` описан через порт: строки эталона, ветви `mirror`/`rotate`, вопрос «из какой
строки Delphi это следует?». На задаче, где результат - текст (вычитка, сценарий, слайды,
презентация, отчёт), этап не отменяется, а переводится: эталон - **исходный текст человека**, а
эквивалентность - требование, чтобы каждый факт в результате следовался из него.

Механика та же, что при сверке чисел: выписать числа и имена исходника, выписать их же из
результата, сравнить множества. Проверено на задаче с презентацией: из девяти находок адвоката **пять** оказались домыслами -
роль человека («руководитель» превратился в «руководителя проекта»), причинная связь, которой в
черновике нет, придуманное обоснование метрики и, самое дорогое, тезис, **противоречащий другой
части того же доклада**. Ни одну из них не видно при чтении результата как самостоятельного
текста: он гладкий и убедительный, и именно поэтому проверять его надо против источника, а не на
внутреннюю связность.

Отсюда правило для правки: домысел закрывается либо возвратом к формулировке источника, либо
явной пометкой на самом артефакте («добавлено не из черновика»). Молча оставить добавленное
нельзя - человек будет произносить это как своё.
