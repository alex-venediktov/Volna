# Локальный HTML проверяется печатью в PDF, а не браузерным расширением

**тип:** приём · **предмет:** сверка локального артефакта · **этапы:** plan, visual, implement
**раздел:** volna

**вывод:** браузерное расширение на `file://` не идёт («Can't interact with browser-internal or
unparseable URLs»), и на этом сверка локальной страницы обычно и заканчивается - `visual`
сводится к «посмотри сам». Обходной путь есть и он полный: **headless Chrome печатает файл в
PDF, а PyMuPDF рендерит страницы в PNG** - дальше картинку видно так же, как скриншот.

```
chrome.exe --headless=new --disable-gpu --no-pdf-header-footer --window-size=1400,900
  --print-to-pdf="<out>.pdf" "file:///<path>.html"
```

Это находит то, чего не видно ни в разметке, ни в `grep`. На презентации таким образом вскрылось,
что **`@media (max-width:760px)` схлопывал двухколоночную сетку при печати**: на экране колонки
были, в PDF - нет, и самый плотный слайд уезжал на вторую страницу. Ни один статический признак
на это не указывал. Лечится явным `grid-template-columns` внутри `@media print`.

Того же прогона два попутных вывода: тёмная тема системы уезжает в PDF, если не переопределить
палитру в `@media print`, а графика на фонах и тенях теряется целиком - [[flow-print-loses-backgrounds]].
И проверять надо **число страниц**: «один слайд - одна страница» это `page_count == число
секций`, лишняя страница означает переполнение, а не косметику.

**связи:** [[flow-print-loses-backgrounds]], [[flow-ask-only-where-stop]]
