# Признак прямого запуска по концу имени файла засчитал запуском и тест

**тип:** постмортем · **предмет:** запуск CLI и его тесты · **этапы:** implement, unit-tests
**раздел:** project

**вывод:** новый CLI `bin/volna-doc.mjs` определял прямой запуск строкой
`process.argv[1].endsWith("volna-doc.mjs")`. Имя тестового файла - `bin/test-volna-doc.mjs` -
кончается ровно на ту же подстроку, поэтому при `node bin/test-volna-doc.mjs` первым делом
отрабатывал сам CLI: печатал справку и завершал процесс до единой проверки. Набор выглядел
зелёным (код возврата 0, ни одной строки `FAIL`), не выполнив ничего.

Почему проскочило: харнес печатает `FAIL` только на упавшей проверке, а тишина и нулевой код
выглядят как успех. Ни одна проверка не утверждала, что проверки вообще были.

**страховка:** признак прямого запуска сверяется по полному пути
(`resolve(process.argv[1]) === fileURLToPath(import.meta.url)`), как в `bin/volna-wiki.mjs`;
в наборе есть проверки кодов возврата CLI - они падают, если `run` не вызывается.

При заведении нового инструмента признак копируется из соседнего `bin/*.mjs` целиком, а первый
прогон нового набора читается глазами: сравнить число строк `OK` с числом `check` в файле.
