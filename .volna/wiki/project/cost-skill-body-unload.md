# Разгрузка тела скилла: делить по частоте обращения, а не по объёму

**тип:** направление · **предмет:** цена on-invoke, вынос в references · **этапы:** plan, capture
**зона:** cost · **раздел:** project

**вывод:** тело `SKILL.md` оплачивается при каждом открытии скилла в новом контексте (после
`/compact` — заново). Разгрузка в `references/` работает, но только при правильном делении.

**Правило:** в теле остаётся то, к чему обращаются **при каждом** применении скилла; уезжает то,
что нужно **в конкретный момент и один раз** — устройство, обоснования, разбор редких случаев.
Вынесенное, если его читают на каждом этапе, обходится **дороже**: два чтения вместо одного плюс
круг «прочитал скилл -> понял, что нужен ещё файл».

Замер на `volna-journal` (0.1.31 -> 0.1.32): тело 249 -> 133 строки, on-invoke **6.2k -> 3.1k**,
ровно вдвое. Осталось в теле: формат секции лога, подпункты «Состояния», правило метки одной
строкой, правила записи. Уехало: устройство двух файлов и раскладка, сборка идентификатора,
потолок «Состояния» и что в него не идёт, запреты по времени, вопросы чек-пойнта.

Два следствия, которые видно только по замеру:

- **суммарный объём растёт** (249 -> 337 строк с `references/`): в вынесенных файлах появляется
  место для обоснований, которых в теле быть не должно. Выигрыш не в сумме, а в том, что читается;
- **always-on не меняется** (~1 179 до и после): инвентарь считает `description`. Правка тел
  на постоянную часть бюджета не влияет никогда — см. [[cost-plugin-cost-measurement]].

Ссылки у потребителей при выносе надо править: вместо «скилл `volna-journal`, «Время в метках»»
писать «`volna-journal`, `references/time.md`» - иначе этап ищет раздел, которого в теле уже нет.

**Работает и для команд, не только для скиллов.** У `commands/` подкаталогов нет, но команда
может указать файл внутри плагина, и модель его прочитает - так устроены 13 этапных команд,
читающих `skills/volna-flow/stages/<этап>.md`. Замер на `doctor` (0.1.32 -> 0.1.33): вынесена
треть тела (раздел сверки скиллов), on-invoke **4.6k -> 3.5k, -24%**. Вынос трети даёт меньше,
чем вынос половины: у `volna-journal` было -50%. При выносе обязательно назвать **условие, когда
файл открывать**, иначе он будет читаться всегда и экономии не будет.
