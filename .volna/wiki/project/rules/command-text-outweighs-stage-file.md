# Текст команды весит больше правила в файле этапа

**тип:** направление · **предмет:** команды и инструкции этапов · **этапы:** implement, capture
**раздел:** project

**вывод:** модель читает `commands/<этап>.md` первым, и неверное утверждение там перевешивает
верное правило в `stages/<этап>.md`. Значит правка правила, задевающая выбор ветви или условие,
обязана попасть в **обе** точки.

Наблюдение: `commands/close.md` утверждал безусловно «`$ARGUMENTS` содержит причину - это ветка
Б». При пустом аргументе подстановка читалась как факт, и закрытие **дважды** пошло по ветке
«изменений кода не потребовалось» - при том что код был изменён, а PR уже слит. `stages/close.md`
при этом первым делом требовал определить ветвь по состоянию задачи.

Починка не в тексте, а в признаке: ветвь определяется **журналом** (секция `deliver` с номером
задачи-фикса и PR, тип задачи), а команда при пустом аргументе прямо запрещает предполагать.

Повтор на второй задаче и показал, почему правки одной инструкции этапа было мало.
