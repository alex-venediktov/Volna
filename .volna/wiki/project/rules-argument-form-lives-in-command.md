# Новая форма идентификатора задачи начинается с текста команды, а не с кода

**тип:** направление · **предмет:** формы аргумента команды · **этапы:** implement, advocate, capture
**зона:** rules · **раздел:** project

**вывод:** какую форму аргумента команда считает номером задачи, а какую свободным текстом,
решает **текст `commands/<команда>.md`**, а не код. Поддержка нового вида идентификатора без
правки этого текста даёт работу, которая выглядит рабочей и молча делает не то.

Наблюдалось при добавлении второго трекера, где идентификатор задачи строковый (`RJDB-2228`).
Клиент, CLI, профиль и файлы этапа были готовы, а `commands/task.md` знал три формы: число из
4-6 цифр, путь к файлу и свободный текст. Ключ подходил под третью: команда завела бы **локальную**
задачу с журналом `TASK-<дата>-<slug>.md`, не сходив в трекер ни разу и не сказав об этом ни
слова. Отказа нет, ошибки нет — есть тихо другая ветвь.

**Признак:** новая форма идентификатора требует правки в трёх местах сразу — `argument-hint` и
таблица форм в команде, таблица входа в файле этапа, разбор в коде (у «Волны» это
`mentionedTask()` в `hooks/preamble.mjs`). Пропуск любого из трёх виден только по последствиям.

**Побочное:** форма `[A-Z]+-\d+` совпадает и с обычными словами через дефис (`UTF-8`, префикс
`TASK-`), поэтому отбор кандидата обязан спрашивать, есть ли журнал, а не брать первое совпадение.
