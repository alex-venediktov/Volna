# Цена хода - накопленный контекст, а не сделанная в ходе работа

**тип:** ограничение · **предмет:** расход токенов по этапам · **этапы:** plan, capture
**зона:** cost · **раздел:** project

**вывод:** каждый ход модели заново читает весь контекст сессии (чтением кэша), поэтому ход в конце
длинной задачи стоит дороже хода в начале, даже если в нём ничего не делается. На задаче из 11
этапов одним контекстом чтение кэша составило 98% входа, контекст вырос с 76k до 152k, а
`deliver`, `close` и `cleanup` без правок кода прочитали 3.0M - больше, чем `implement` с
`advocate` (2.5M). Замер 25.10.2026, `bin/volna-cost.mjs`, таблица - `docs/COST.md`.

Следствия для устройства флоу:

- экономия даёт больше всего там, где **не растёт контекст**, а не там, где короче текст правил:
  подагент, которому нужен только журнал, запускается свежим, а не форком - форк читает весь
  контекст оркестратора каждым своим ходом;
- число ходов на поздних этапах стоит дороже, чем на ранних: лишний вызов инструмента на `close`
  оплачивается полным контекстом задачи;
- сравнивать этапы и версии можно только таблицами того же замера: одна задача - не закономерность.
