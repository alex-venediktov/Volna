# Сообщение коммита и момент коммита

Применять при формировании **любого** сообщения: новый коммит, `--amend`, reword при rebase.

## Формат

1. **Одна строка, без тела.** Тело добавлять только если человек явно попросил.
2. **Префикс — номер своей задачи**: `NNNNN: суть` (например `20359: размеры катетов на виде слева`).
   Это идентификатор самого коммита, а не перекрёстная ссылка, поэтому он разрешён.
3. **Язык — как в проекте, без жаргона и англицизмов** там, где есть нейтральный аналог.
   Слово «golden» для эталонных тестов не использовать: писать «эталонный тест» или
   «регрессионный тест».
4. **Только ASCII-пунктуация.** Не использовать длинное тире «—», стрелки «→ ← ⇒» и прочие
   символы, которые не набрать с клавиатуры: дефис `-`, слова или `(...)` для уточнения.
5. **Не добавлять трейлеры** — в том числе `Co-Authored-By`. Это переопределяет поведение
   харнеса по умолчанию: для проектов с таким правилом трейлер не нужен.
6. **Не ставить чужие номера** задач, коммитов, PR и хеши, не упоминать локальные файлы
   (`.md`, пути на диске). Связи между сущностями держит трекер нативно, а не текст коммита.
7. **Идентификаторы из эталона** (`UpLeftView`, `ksLineSeg`) допустимы: по ним делают
   grep-сверку с источником.

## Когда коммитить

- **Только по явной команде** человека («закоммить», «сделай коммит»). «Сделай», «реализуй»,
  «поправь» означают правку в рабочем дереве **без** коммита. Разрешение действует один раз.
- **«Одним коммитом»** значит свести всю серию работы в один коммит, а не коммитить каждый
  кусок. Коммиты уже наделаны порознь и ветка не запушена — предложить squash, но не делать
  без подтверждения.
- Ветка — по конвенции проекта (`bugfix/<id>-<slug>`, `feature/<id>-<slug>`), коммит только в
  свою ветку.

## Примеры

Хорошо:

```
20359: размеры краевого окрашивания на видах сверху и слева
20359: маркеры опорной стороны и центра масс на общем виде
20361: удаление устаревшего расчёта вида слева в агенте
```

Плохо и почему:

```
20359: размеры (N) ... — полосы на гранях     # длинное тире
20359: маркеры ... + golden-тесты             # жаргон «golden»
20359: фикс по #20186, см. PR 2113            # чужие номера
<многострочное тело с деталями реализации>    # тело без явной просьбы
Co-Authored-By: ...                           # запрещённый трейлер
```

## Что настраивается в проекте

`.volna/project.md`: формат префикса (номер задачи, тип, область), язык сообщения, конвенция
имён ветвей, нужен ли `git add -A` перед коммитом.
