# Стиль комментариев в коде

## Формат

Комментарий — **одна строка**: `что делает (откуда)`.

- **что** — техническое назначение, а не пересказ кода строкой ниже;
- **(откуда)** — источник в скобках: ссылка на строку эталона `<модуль>:NNNN`, если это порт.

Больше ничего: без многострочных разборов, без «почему», «как», «раньше было».

Хорошо:

```
// Центр масс только в сводном режиме, не на операционных представлениях (<модуль>.pas:19226).
// Диагонали не выводятся для трёх типов обработки (<модуль>.pas:42911).
```

Плохо: многострочный блок с разбором ветвей, цитатами кода, ссылками на переписку и скриншоты.

## Запрещено

- **«по указанию пользователя», «по сверке», «на скриншоте видно», «наблюдение»** —
  обоснованием служит только ссылка на эталон. Исключение — значение, которое человек задал
  явно: тогда `// по указанию: <правило>` и никакого подбора.
- **Номера задач, PR, тредов** (`#12345`, `PR 678`, `Task 1.2.3`). Связи держит трекер, не код.
- **Фамилии, имена файлов-скриншотов, история итераций** («итер.3», «после обсуждения»).
- **Описание прежнего или неверного поведения** («а не X», «раньше давало Y»). В коде живёт
  только корректное целевое поведение; почему стало так — в журнале задачи.
- **Сленг и жаргон** — включая англицизмы, у которых есть нейтральный аналог: «признак», а не
  «флаг»; «условие», а не «гейт»; «эталонный тест», а не «golden».
- **Труднонабираемые символы** — длинное тире «—», стрелки «→ ← ⇒», типографские кавычки.
  Только то, что набирается с клавиатуры: дефис `-`, `->`, прямые кавычки. Комментарий, который
  нельзя воспроизвести поиском, ломает grep-сверку с эталоном.

## Допустимо

- Ссылка на эталон `<модуль>:NNNN` — это технический ориентир, а не номер трекера.
- Doc-комментарий публичного API (`/// <summary>`, JSDoc) — так же кратко и по сути.
- Идентификаторы из эталона как имена (имена процедур, типов и констант источника) — это не
  жаргон, а имя из источника, по которому делается grep-сверка.

## Область правила

Только **комментарии в коде**. Формат сообщения коммита — скилл `commit-style`;
записи о ходе работы — журнал задачи (`volna-journal`), а не комментарии.

Правила касаются **добавленных и изменённых строк**. Существующие легаси-комментарии массово
не переписываем: это отдельная задача, а не побочный эффект правки.

## Что настраивается в проекте

`.volna/project.md`, раздел «Конвенции»: язык комментариев, допустимая пунктуация (например
только ASCII: `->`, `-`, прямые кавычки), формат ссылки на эталон, требование doc-комментариев
для публичного API.
