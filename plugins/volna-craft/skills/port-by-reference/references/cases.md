# Порт по эталону: разбор антипаттернов

Реальные провалы порта, обезличенные до сути. Читать при сомнении «можно ли так».
Основные правила — в `../SKILL.md`.

## Так делать нельзя

- ❌ **Условие «из головы» вместо гейта эталона.** Написали проверку вида «если тип параметра
  не равен единице», хотя в эталоне решение принимает отдельная функция-гейт по обработкам.
  Совпало на первом примере — развалилось на втором.
- ❌ **Перекрасить под скриншот.** На эталонном изображении элемент оранжевый → покрасили
  элемент в оранжевый. Источник цвета оказался совсем другим (свойство уровня документа,
  приходящее из загрузчика), и правка сломала остальные случаи.
- ❌ **Подобрать число под эталонное значение**, не перенося формулу. Сходится на одном
  наборе данных и врёт на всех прочих.
- ❌ **Назвать проверку или константу иначе, чем в эталоне**, или повесить имя из эталона на
  другое условие. Классика: два кода ошибки поменяны местами — условие «А совпало с Б»
  помечено именем, которым в эталоне называется противоположная ситуация. Тесты это не ловят.

## Почему правила именно такие

- **Наивная формула вместо функции эталона (правило 1).** Точку привязки на дуге вычислили
  так же, как на прямом отрезке («какой конец ближе»), вместо переноса специальной функции
  эталона с инверсией по типу дуги и признаку зеркала. Маркер сел на противоположный конец —
  и только на дугах, то есть в редком случае, который никто не проверял.
- **Перепутанные имена (правило 2).** См. выше: имя из эталона попало на другое условие.
  Ошибка живёт в коде долго, потому что поведение «почти правильное».
- **Реконструкция по словам (правило 3).** Логику размещения элементов собирали по описанию
  человека — сколько их, на каком расстоянии, где именно, — вместо переноса двух конкретных
  процедур эталона. Каждый раунд правок был неверным по-новому: описание не содержало ветвей,
  которые есть в коде.
- **Неполный порт (правило 4).** Из процедуры перенесли только образмеривание, а штриховой
  контур, эллипсы, легенду и полный штамп опустили; часть элементов собрали из готовых методов
  своего проекта вместо порта соответствующих функций эталона. Результат разошёлся с эталоном
  сразу по нескольким пунктам, причём каждый пункт выглядел как отдельный «мелкий баг».

Общий признак всех случаев: **порт выглядел законченным и проходил проверку на том примере,
на котором его писали**. Поэтому чек-лист требует не «работает», а «каждая ветка со ссылкой».
